# 활동 사진 관리 UI 미리보기

개발 서버에서 `http://localhost:3000/history/manage-preview`로 접속합니다. 다른 포트를 사용하면 변경합니다. 개발 환경에서만 접근할 수 있고 운영 빌드는 404입니다. 관리자 인증이 구현된 화면이 아닙니다.

## 완료된 범위

- 가상 기록에 [데모] 표시, 실제 활동 사진 대신 브랜드 로고 사용.
- 정규 세션/특별 활동 목록과 기수(9~1기)/연도(2026/2025) 필터.
- 필수 카테고리·기수 또는 연도·제목·날짜·설명·대표 사진 검사.
- 제목 120자, 설명 2,000자 안내·검사. 공백만 입력할 수 없음.
- 특별 활동 날짜는 선택한 연도와 일치해야 함. 실제 존재하는 날짜인지 검사.
- 대표 사진 1장, 추가 사진 선택·복수 미리보기·개별 취소. 대표 교체와 취소도 가능.
- 형식/MIME/파일 시그니처 및 실제 이미지 디코딩으로 잘못되거나 손상된 파일 검사.
- 기존 값으로 수정, 삭제 전 확인(초기 초점은 취소), 작성 중 닫기·취소·Escape 시 유실 확인.
- Tab/Shift+Tab 모달 내부 순환, 닫기 후 초점 복귀, 필수 오류 시 해당 입력 초점 이동.
- 등록·수정·삭제는 현재 탭의 React 메모리 목록에만 반영. 실제 저장·업로드 요청 없음. 새로고침하면 가상 초기 목록으로 복원. localStorage에도 저장하지 않음.
- 파일 미리보기 URL은 임시 blob URL. 사용하지 않는 URL과 페이지 종료 시 URL을 해제함.

## 확정된 개발용 사진 등록 기준

활동 사진은 아래 기준으로 UI에서 검사합니다. 참여 후기의 사진 정책과 공통 업로드 설정은 변경하지 않습니다.

- JPG/PNG/WebP, 장당 최대 4.5MiB.
- 대표 사진 1장 + 추가 사진 최대 9장 = 전체 최대 10장.
- 전체 파일 합계 45MiB 이하.

용량은 1MiB = 1,048,576바이트로 검사합니다. 장당 최대 4.5MiB = 4,718,592바이트, 합계 최대 45MiB = 47,185,920바이트입니다.

사진 순서 변경과 공개/비공개는 실제 저장 연동 시 구현합니다.

대표 사진 자리를 남기기 위해 대표 미선택 시에도 추가 사진은 9장으로 제한합니다. 현재 값은 로컬 UI 검사용이며 서버·Storage 정책이 아닙니다. 자동 압축/리사이즈는 하지 않습니다. 실제 연동 시 서버에서도 파일·용량·장수를 검증해야 합니다. Next.js 서버 액션 기본 크기 제한을 고려한 별도 업로드 설계도 필요합니다.

## 기존 갤러리와의 호환

기존 `HistoryPhoto` 타입과 갤러리는 수정하지 않았습니다. 이 폴더의 `Activity`는 대표 사진과 추가 사진을 관리하는 UI 모델입니다.

- 정규 세션: `category: regular`, `cohort: 9~1` → 기존 기수별 필터와 호환.
- 특별 활동: `category: special`, `year: 2026/2025` → 활동 날짜와 연도를 일치시켜 기존 `date.slice(0,4)` 필터와 호환.
- `toHistoryPhoto()`는 대표 사진의 URL·대체 텍스트와 제목·날짜·설명, 추가 사진 목록을 기존 `HistoryPhoto`와 호환되는 구조로 변환하는 준비 함수입니다. 이 함수나 데모 데이터를 실제 `/history` 갤러리에 연결하지 않았습니다.
- 실제 연결 시 검증된 영구 URL과 공개·초상권 동의가 확인된 자료를 사용해야 합니다. blob URL은 저장할 수 있는 영구 사진 주소가 아닙니다. `additionalPhotos`로 전달된 추가 사진은 사진 상세 모달에서 표시할 수 있습니다. 관리 데모와 공개 갤러리의 실제 데이터는 연결하지 않았습니다.

## 연동 전 남은 작업

실제 관리자 인증·서버 권한 검사, 활동 테이블/Storage/RLS 설계·승인, 파일 업로드·삭제 및 실패 시 정리, 영구 저장·갤러리 연결, 관리자/일반 계정 간 권한 검증이 필요합니다. 이 UI는 권한 보장을 제공하지 않습니다. 공통 인증·관리자 페이지·SQL·Storage 정책을 변경하지 않았습니다.

## 검증 결과

- `npm run lint`: 경고 없이 통과.
- `npm run build -- --webpack`: TypeScript 포함 통과.
- DB 환경변수가 없는 임시 복사본의 개발 서버에서 Chrome 1280px/390px 검사 통과: 목록·빈 분류·기수/연도 필터, 필수값·공백·날짜/연도 불일치, MIME/시그니처·손상 파일·장당 크기·총 크기·장수 제한, 복수 미리보기·개별 취소, 작성 중 유실 확인, 수정 초기값, 데모 등록·수정·삭제, Tab/Escape/초점 복귀, 가로 넘침 없음.
- 관리 화면 점검 중 실제 등록/수정/삭제 네트워크 요청과 Supabase 요청 모두 0건.
- 새로고침 시 초기 데모 목록 복원 확인.
- 최종 운영 빌드에서 `/history/manage-preview` HTTP 404, 응답 내 관리 UI·데모 기록 미포함 확인.
- Commit/Push 없음.

## 선택 사진 슬라이드 확인

대표 1장과 추가 9장을 고른 뒤 필수 활동 정보를 입력하고 “데모 목록에 추가”를 누릅니다.
해당 카드의 “사진 슬라이드 미리보기”에서 선택한 10장을 기존 갤러리 상세창으로 확인합니다.
이는 현재 탭의 메모리 미리보기이며 /history의 공개 목록이나 DB에 저장하지 않습니다.
사진 선택 직후 파일 입력의 이름은 비워지지만 선택한 사진은 폼의 미리보기에 표시됩니다.

- 좌우 버튼·방향키·썸네일로 이동하고 마지막 다음은 첫 사진, 첫 사진 이전은 마지막으로 순환합니다.
- 모바일에서는 사진 영역을 좌우로 48px 이상 밀어 이동합니다. 세로 스크롤·확대·짧은 터치는 사진을 넘기지 않습니다.
- 사진 번호, 제목·날짜·설명을 표시합니다. 닫기·ESC로 종료하고 이전 초점으로 복귀합니다.
- 직접 조작 확인: 폼의 전체 썸네일, 11장째 거부, 모바일 스와이프, Tab/Shift+Tab·ESC·닫기 후 초점을 확인합니다.

활동 사진 기준은 MiB(1024 기반)입니다: 장당 4.5MiB = 4,718,592바이트, 합계 45MiB = 47,185,920바이트.
공통 기준은 `src/lib/history-activities/photo-policy.ts`를 사용하며 후기 사진 정책과 분리합니다.
파일 용량과 HTTP 본문 용량은 다릅니다. Vercel의 4.5MB 본문 제한에는 multipart 경계와
추가 필드도 포함되므로 최대 크기 파일의 현재 Route 전송은 지원한다고 가정하지 않습니다.
현재 비활성 Route는 임시로 본문을 4,000,000바이트까지 제한합니다. 이는 파일 기준을
낮추거나 Vercel의 정확한 바이트 상한을 확정한 값이 아닙니다. 전송 구조 확정 전 업로드는 비활성입니다.
