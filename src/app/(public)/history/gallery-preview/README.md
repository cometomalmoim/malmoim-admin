# 사진 상세 갤러리 UI

개발 서버의 `/history/gallery-preview`에서 명확히 표시된 [데모]로 확인합니다. 고정 예시 날짜와 브랜드 로고·기본 아이콘만 사용하며 실제 활동 자료가 아닙니다. 운영 빌드에서는 404입니다.

- 기존 갤러리 사진을 버튼으로 열어 큰 사진, 제목·카테고리·기수·날짜·설명을 표시합니다. 기존 카드 크기, 기수·연도 필터와 더 보기 구조를 유지합니다.
- `HistoryPhoto.additionalPhotos?: { src: string; alt: string }[]`로 같은 활동의 추가 사진을 전달할 수 있습니다. 없으면 대표 사진 한 장만 표시합니다.
- 여러 사진은 이전/다음 버튼, 좌우 방향키, 썸네일로 선택합니다. 처음과 마지막 사이를 순환합니다.
- 네이티브 모달, Tab/Shift+Tab 내부 순환, Escape 닫기와 기존 사진 버튼으로 초점 복귀를 지원합니다. 이미지 로딩 실패 시 안내를 표시합니다.
- 관리 UI의 `toHistoryPhoto()`는 추가 사진도 호환 형식으로 변환합니다. 실제 관리 데이터와 공개 갤러리는 연결하지 않았습니다. 영구 저장·공개 동의·실제 사진 URL은 추후 연동 대상입니다.

## 검증

`npm run lint`, `npm run build -- --webpack` 통과. 실제 `npm run dev` 서버 localhost:3000에서 Chrome 1280px/390px로 상세 열기, 정보·사진 수, 다음/좌우 방향키/썸네일, 단일 사진, 기수·연도 필터, 모달 화면 넘침 없음, Tab/Escape/초점 복귀를 확인했습니다. Blocking Route/hydration 오버레이와 DB·변경 요청이 없었습니다. 운영 경로 404 및 데모 기록 미노출도 확인했습니다.

`/history/manage-preview`는 렌더링 중 Date.now/Math.random 호출이 없고 데모 날짜가 고정되어 있어 시각 관련 코드는 수정하지 않았습니다. 입력 날짜를 해석하는 new Date(입력값)와 UUID 생성은 이벤트 처리에만 사용합니다.
