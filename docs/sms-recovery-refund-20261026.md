# 문자 준비 오류와 수동 환불 완료 안내

- 준비 RPC의 명시적 오류를 관리자용 사유로 변환. pending_or_unknown이면 실제 차단 작업 상태와 초안 소유자를 조회하여 구분하며 조회 실패 시 원인을 추정하지 않는다.
- 내 초안만 취소 후 재준비. 선택한 신청자 범위로 제한하고 기존 RPC의 생성 관리자·draft 제약을 유지한다. 다른 관리자 초안, queued/dispatching/accepted/unknown은 취소하지 않는다.
- 결과 확인은 현재 작성창 안에서 해당 신청자 이력을 연다. accepted의 기존 도달 조회 버튼을 재사용하며 unknown 자동 재시도는 하지 않는다.
- 환불 완료 템플릿: 운영진 명시 확인 + 최신 refunded 상태 + 전용 custom 완료 템플릿을 서버에서 검증. 범용 작성창에서 같은 완료 템플릿을 선택해도 확인이 필요하다.
- 확인 시 기존 manage_event_application RPC로 내부 메모에 준비 배치 식별자와 확인 시각을 추가한다. 기존 필드를 보존하고 revision 충돌 시 멈춘다. 기존 관리자 변경 감사에 담당자와 수정 시각이 남는다. 이 메모는 운영진 확인 기록이며 은행 이체 증빙이나 실제 환불 원장이 아니다.
- 확인 메모 저장 뒤 최신 revision을 다시 읽어 문자를 준비한다. 같은 배치의 재요청은 확인 메모를 중복 추가하지 않는다. 이후 준비 실패 시에도 확인 메모는 남을 수 있으며 실제 발송을 뜻하지 않는다.
- 실제 납부액/환불액 자동 대사나 환불 송금 실행은 추가하지 않는다. 완료 문구에 금액을 추정하여 넣지 않는다. 확인 체크는 대상·본문·언어·공통금액 변경 시 해제된다.
- 업체 접수는 ‘발송 완료 · 도달 확인 중’, delivered는 ‘발송 완료 · 도달 성공’. queued/dispatching/failed/unknown은 완료로 표시하지 않는다.

DB 스키마 변경 없음. 실제 SMS는 검증 중 발송하지 않는다.
