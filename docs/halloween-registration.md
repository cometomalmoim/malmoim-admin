# A조 할로윈 신청 저장 연결

## 범위
이름·전화번호·말모임 참가 이력·선택 활동명·개인정보 필수 동의·마케팅 선택 동의. 기존 9기 DB는 변경하지 않고 응답 테이블을 추가한다. security_invoker 통합 뷰로 어드민 목록/개요 건수를 연결한다. 기존 입력 규칙과 상태는 유지한다.

공개 접수는 비활성이다. registration_enabled, applications_open, published 상태, 모집 기간, 개인정보 안내·버전이 모두 충족되어야 제출 가능하다. 사용자 승인 없이 활성화하지 않는다. 개인정보 안내 최종 문구와 3개월 이후 처리 기준, 참가비 안내를 공개 전에 확정한다.

사용자 요구: 3개월 보유, 자동삭제 하지 않음. retention_review_at은 접수일+3개월의 검토 시점으로만 저장하며 삭제 스케줄/발송 기능은 추가하지 않는다. 마케팅 선택 동의는 신청 필수 동의와 별도 저장하고 거부해도 신청 가능하다. 실제 마케팅 발송은 범위 밖이다.

## 1. 문제사항
할로윈 랜딩의 신청 폼은 비활성이고 기존 DB 필수 질문은 9기 전용이라 그대로 저장할 수 없었다.
## 2. 개선 경험
할로윈 응답 저장소와 제출 함수를 추가하고 이벤트 ID로 신청자 목록·개요 건수에 연결했다.
## 3. 진행 과정
기존 필드·보호 경계 확인 → 별도 응답 테이블 → 모집/동의/중복 검증 → 가상 데이터 DB 테스트 → 빌드 및 배포 후 브라우저 검증.
## 4. 측정
입력 단위 테스트 3개 통과. DB 검증: 저장·같은 요청 재시도·연락처 중복·필수 동의·테스트 이벤트 격리·통합 목록 건수·마케팅 미동의·비관리자 RLS·익명 조회 금지·공개 접수 닫힘 통과. SQL 권한 시뮬레이션이며 실제 일반회원 로그인 테스트와 구분한다. 웹 제출·운영 목록 확인은 별도 결과 기록. 시간 단축·실제 모집 실적 미측정.
## 5. 어려움과 해결
9기 희망 반 필수 제약을 완화하지 않고 별도 응답 구조와 통합 조회 뷰로 기존 기능을 보존했다. 010과 +82 표기를 통합해 중복 신청 우회를 줄였다.
## 6. AI 활용
업무 규칙을 입력·DB·관리자 화면에 나눠 적용하고 실측 결과와 미검증을 구분했다.
## 7. 포트폴리오
AI를 활용해 행사별 신청 저장과 어드민 응답 조회를 연결하고, 가상 데이터로 중복·동의·권한 경계를 검증했습니다.
## 8. 자소서
행사 신청 폼과 기존 기수별 데이터 구조의 차이를 확인하고 할로윈 응답 저장·관리자 조회 연결을 담당했습니다. 기존 데이터를 보존하며 실패·중복·권한 조건을 검증했습니다. 실제 모집 적용과 가상 데이터 검증을 구분해 성과를 기록했습니다.
