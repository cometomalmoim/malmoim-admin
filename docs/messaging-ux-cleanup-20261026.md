# 관리자 문자 화면 정리

- 상태 저장 → 중간 저장 안내창 → 문자 준비의 중복 이동을 없애고 관련 문구가 선택된 공통 작성창을 바로 연다. 모으기 모드는 작성창 상단에서 시작한다. 실제 발송은 여전히 최종 검토 후 운영진의 명시적 버튼 조작으로만 실행한다.
- 작성 / 최종 확인 / 결과 화면을 구분한다. 결과에서는 이전 단계 비용·확인 체크·수정·외부 이동 안내를 제거한다. 1명 발송은 본문을 바로 보여주며, 발송 이력은 현재 화면 안에서 연다. 처리 완료 후 닫기 버튼을 잠그지 않는다.
- 최종 검토의 확인 체크와 발송 버튼을 하나의 명시적 ‘확인 후 N건 발송’으로 합친다. 실제 환불 처리 확인 체크는 별도 의미이므로 유지한다. SQL의 상태·버전·재발송·중복 방지는 유지한다.
- 실제 발송 결과는 서버에서 batch별 저장 상태를 조회하여 표시한다. API 요청 성공을 휴대폰 도달 성공으로 추정하지 않는다. 결과 조회 실패는 확인 필요로 표시한다. 승인되지 않은 남은 draft만 취소하며, queued/accepted/unknown은 취소하거나 재시도하지 않는다.
- 이력은 실제 문자 1건을 1행으로 표시한다. 이벤트·문구·버전별 가상 묶음을 제거하고 한 번 펼치면 본문과 처리 이력을 함께 불러온다. 주요 필터는 이벤트·상태·이름, 날짜·유형·언어는 추가 필터로 둔다. 발송 시각은 accepted/delivered 변경 이력에서 읽고, 없는 경우 준비 시각이라고 명시한다. 소유자가 아닌 초안은 취소 버튼을 표시하지 않는다.
- 신청 접수 / 입금 요청 / 입금 확인 / 선발 합격 / 최종 참가 확정 / 불합격 / 대기 / 환불 요청 접수 / 환불 완료 / 행사 안내 / 참여 리마인드의 한국어·영어 기본 예시 제공. 문의 답변 전용 링크 예시는 번호 직접 입력 흐름에 유지. 금융·승인 상태 확인이 필요한 예시는 이벤트 신청자 작성창에서 사용한다.
- 기본 문구와 같은 이름으로 저장한 이벤트 문구는 기본 버튼에서 우선 사용한다. 그 외 저장 문구만 별도 선택란에 표시하여 동일 문구를 중복 나열하지 않는다. 기본 예시는 템플릿 관리에서도 편집 초안으로 불러올 수 있다. 예시 전체를 운영 DB에 자동으로 중복 저장하지 않는다.

DB 스키마 변경 없음. 검증 중 실제 SMS를 발송하지 않는다.
