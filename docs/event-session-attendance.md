# 이벤트별 날짜 출석 / 전체 참여 이력

이벤트 운영: `/admin/events/[slug]/attendance`. 진행 날짜(한국 날짜)와 회차 이름을 추가하고 날짜를 선택합니다. 같은 이벤트의 같은 날짜는 한 회차입니다. 여러 날짜는 각각 독립적인 출석입니다. 한 날짜에 여러 시간대 출석은 이번 범위에 포함하지 않습니다.

참가 확정과 동일 인물 연결은 이벤트 단위입니다. 출석은 확정된 참가자에게 날짜별로 기록합니다. 실제 이벤트의 미래 날짜는 차단합니다. 테스트 이벤트만 미래 가상 기록을 허용합니다. 날짜 수정은 출석이 없거나 전부 미기록일 때만 가능합니다. 제목은 수정 가능합니다. 기록 삭제 기능은 제공하지 않습니다.

기존 날짜 없는 출석은 `legacy_attendance`에 보존합니다. 임의 날짜 배정이나 출석 회차 수 추정을 하지 않습니다. 이벤트 요약 attendance는 기존 기록과 새 회차들의 참석 증거를 합칩니다(참석 우선, 다음 노쇼/미참석, 없으면 미기록). 최소 한 번 참석한 이벤트는 기존 이벤트 참여 횟수에서 한 번만 집계합니다. 수료증의 기존 이벤트 참석 판정 로직은 유지합니다. 모든 회차 이수 여부로 수료증을 제한하는 정책은 별도입니다.

전체 화면: `/admin/participants`, 사이드바 이름은 ‘전체 참여 이력 관리’. 사람별 참여 이벤트 수, 날짜가 있는 출석 회차 수, 최근 실제 출석일, 날짜별·이벤트별 이력을 조회합니다. 테스트는 실제 집계에서 제외합니다. 날짜별 이력 최근 100건과 전체 기록 건수를 표시하고, 수정을 위해 해당 이벤트 날짜 화면으로 이동합니다. 사람 검색은 기존 최대 50명입니다. 이벤트 명단은 25명 페이지, 상태 분류는 현재 페이지 기준입니다.

DB 적용: `025_event_session_attendance.sql`. 기존 `011` 참여 이력 및 `024` 신청자 아카이브가 필요합니다. 관리자 전용 RLS와 읽기 권한, 전용 RPC만 쓰기 허용. 이벤트 행 잠금 아래 회차 버전/참여 버전을 검사하고 출석·이벤트 집계·감사를 한 트랜잭션에서 처리합니다. 회차가 등록된 이벤트는 기존 이벤트 출석 RPC가 집계 출석을 덮어쓰지 못하며 참가 상태/메모만 수정합니다. 날짜별 기록이 있으면 전체 미기록 전까지 기존 사람 연결 잠금이 유지됩니다.

검증: `node --experimental-strip-types --test tests/session-attendance.test.mjs tests/participation.test.mjs tests/certificate-attendance.test.mjs`; `supabase/tests/event_session_attendance.sql`은 명명된 테스트 이벤트/가상 신청자와 롤백 임시 이벤트를 사용합니다. 운영 데이터는 테스트 대상으로 사용하지 않습니다. 운영 DB 적용은 명시 승인 후 수행했습니다.

문자 연동과 PR #28 적용/병합/배포는 보류 상태를 유지합니다.
