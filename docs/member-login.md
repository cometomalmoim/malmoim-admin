# 사용자 홈페이지 로그인

현재 브랜치에서 기존 Supabase 이메일·비밀번호 인증을 공유합니다.

- 회원 로그인: `/auth/login` → 성공 시 `/`.
- 홈페이지와 공개 페이지의 계정 메뉴: 미로그인 시 로그인 진입만 표시(가입 링크는 회원 로그인 화면에 유지), 로그인 시 프로필 아이콘 아래 이메일과 로그아웃.
- 회원 로그아웃: 기존 local 세션 로그아웃 후 `/`.
- 기존 관리자 `/login` → `/admin`, 로그아웃 → `/login` 동작 유지.
- 관리자 접근은 기존 `getAdminAccess()`와 `admin_users` 검사를 유지합니다.
- 실제 회원가입·프로필 저장, 역할·권한 관리, DB·RLS·환경변수·Supabase 설정 변경은 없습니다. 후속 프로필 메뉴·가입 준비 화면과 미검증 사항은 signup-profile-plan.md를 참고합니다.

## 재사용 구조

`src/app/actions/auth.ts`의 내부 signIn/signOut 로직을 기존 관리자 Action과 회원 Action이 공유합니다.
기존 LoginForm/LogoutForm의 audience 기본값은 admin이고, 공개 화면에서만 member를 지정합니다.
서버 Supabase 클라이언트와 쿠키 옵션은 유지했습니다.
공개 계정 영역은 Suspense 아래에서 getUser로 확인하며, Proxy는 홈페이지와 공개 페이지에서도 쿠키를 갱신하고 private/no-store 헤더를 반환합니다.

같은 호스트에서는 일반 회원과 관리자가 같은 세션을 사용합니다.
다른 계정 로그인과 local 로그아웃은 같은 세션을 사용하는 다른 화면에도 영향을 줍니다.
현재 도메인 간 쿠키 공유 설정은 추가하지 않았습니다.

## 검증 (2026-10-15)

- `npm run lint`: 통과.
- `npm run build`: 통과 (TypeScript 검사 포함).
- `node --test tests/auth.test.mjs`: 실제 계정·네트워크 없이 공통 인증, 이동 경로, 입력·오류 처리, 관리자 권한 거부, 계정 UI, Proxy 쿠키 갱신을 검증.
- 운영 빌드 브라우저: PC 1440px, 모바일 390px 로그인 진입·메뉴 열기/닫기·가로 넘침 없음 확인.
- 브라우저: 빈 입력·이메일 형식 검증, 비밀번호 표시 전환, 회원 로그인 noindex 확인.
- 브라우저: 비로그인 /admin → 기존 /login 이동, 운영 /preview/admin 404 확인.
- 실제 Supabase 계정 로그인, 인증 후 홈페이지 이동·이메일 표시, 새로고침 유지·만료 토큰 갱신, 실제 로그아웃, 일반 회원/관리자 계정별 통합 검증은 미검증.
- 임의 테스트 계정을 생성하지 않았고 로그인 자격 증명을 전송하지 않았습니다.

## 추가 설정

기존 이메일·비밀번호 인증과 환경 설정을 그대로 사용하므로 이번 기능의 신규 Supabase 설정은 없습니다.
프로젝트의 실제 계정/이메일 인증 상태와 연결 유효성은 별도 통합 확인이 필요합니다.
빌드에서 Supabase SDK가 Node.js 20 이하 지원 중단 예정 경고를 표시했습니다. 런타임 변경은 별도 협의 대상이며 이번 작업에서 변경하지 않았습니다.
