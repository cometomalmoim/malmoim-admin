# A조 개인별 참여 이력·횟수

## 집계 기준
실제 참석으로 기록한 이벤트 수만 참여 횟수로 집계한다. 신청·합격·입금과 독립적이며 자기신고 과거 참여 응답을 횟수로 변환하지 않는다. 테스트 이벤트는 실제 신청/확정/참석 집계에서 제외하고 테스트 참석 수를 별도로 표시한다. 같은 사람은 같은 이벤트에 한 번만 연결할 수 있다.
이름·연락처로 자동 병합하지 않는다. 관리자 확인을 거쳐 신청별 사람 연결을 만들며 검색으로 기존 사람을 찾아 연결한다. 실제 행사 시작 전/일정 미정의 출석 입력은 차단한다(가상 테스트 이벤트 예외). 회차별 출석·회원 계정 동기화·문자·납부 관리는 이번 범위가 아니다.

1. 문제사항: 과거 참여 여부 응답만 있어 실제 참석 횟수와 행사별 이력을 확인할 수 없었다.
2. 개선 경험: 사람과 신청의 명시적 연결, 이벤트별 참가 확정/취소 및 출석 기록, 개인별 실제/테스트 횟수와 대시보드 집계를 구현했다.
3. 진행 과정: 기존 구조 점검 → 실제 참석 기준 사용자 확인 → 별도 DB/관리자 권한 → 가상 이벤트 SQL 검증 → lint/운영 빌드 → PR·배포 후 화면 확인.
4. 측정: 입력 자동 테스트 3개 통과. DB 15조건(동일인 확인, 연결, 확정 조건, 실제 집계, 버전 충돌, 이벤트 격리, 다중 이벤트 연결, 테스트 제외, 수정 반영, 미래 행사 차단, 이벤트 중복 집계 방지, 감사 기록, 일반회원 조회 차단, 일반회원 수정 차단, 익명 수정 금지) 통과. 테스트 변경은 rollback. 웹 검증은 별도 기록. 시간 절감·실제 운영 성과는 미측정.
5. 어려움과 해결: 같은 연락처가 같은 사람이라는 보장이 없어 자동 병합을 피하고 운영진 확인을 필수화했다. 참석 수정 시 집계가 함께 바뀌는 파생 뷰를 사용해 수동 횟수 입력과 불일치를 방지했다.
6. AI 활용: 업무 집계 기준을 DB·화면·권한 검증에 반영하고 가상 결과와 실제 운영 데이터를 구분했다.
7. 포트폴리오: 개인별 행사 참석 이력과 횟수 조회를 구현하고, 테스트 데이터 제외·중복 집계 방지·참석 수정 반영을 가상 데이터로 검증했습니다.
8. 자소서: 신청 여부와 실제 참여가 혼동되는 문제를 발견하고 참석 기준과 동일인 확인 절차를 정리했습니다. 납부·선발 기능과 독립된 이력 구조를 구현하고 집계·권한·동시 수정 경계를 검증했습니다.

협업: 납부/선발 저장 테이블·함수는 변경하지 않음. 공통 신청자 목록에는 참여 이력 링크만 추가. 대시보드·개요·보호 라우터는 새 화면 연결만 변경.
