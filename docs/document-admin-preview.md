# 전자서명 4단계 — 관리자 서류 관리 미리보기

## 범위와 안전 경계

`feat/events-yewon`에서 새 파일만 추가했다. 기존 3단계 파일, 수료증, 신청자 관리, 참여 이력,
문자, 관리자 메뉴/공통 라우터, SQL, 환경변수, 의존성, `supabase/.temp/`은 변경하지 않았다.
DB(운영/로컬), Supabase Storage, 운영 서버, 실제 문자/개인 링크/인증에 연결하지 않는다.
브랜치 전환·병합·커밋·push·PR은 하지 않는다.

기본 데이터는 가상 이벤트 3개·가상 참가자 18명·가상 서류 메타데이터 3개다.
여섯 상태를 각각 3건씩 제공한다. 이름, 요청일·완료일, 응답, 처리 이력은 모두 가상이다.
가상 완료 상태는 실제 서명/보관 완료를 의미하지 않는다. 모든 완료 PDF 파일은 미등록이다.

이번 검증에서는 환경변수를 복사하지 않은 기존 `work/pdf-fields-check` 사본의 서버를 사용했다.

```sh

NEXT_TELEMETRY_DISABLED=1 WATCHPACK_POLLING=true npm run dev -- --webpack --hostname 127.0.0.1 --port 3187
```

기존 proxy의 관리자·공개 인증 matcher 밖에 있다. 미리보기 외의 기존 기능으로 이동하지 않는다.

## 구현 기능

### 템플릿

- PDF 선택·검증 후 브라우저 메모리에 원본과 메타데이터 등록, 이름 등록·수정, 버전 증가.
- 5MiB 이하·50페이지·총 필드 200개, 이 탭의 PDF 원본 최대 10개.
- 페이지별 실제 PDF 미리보기·페이지 선택·50~200% 확대/축소.
- 이름·날짜·여러 서명 필드 추가/드래그/이동/크기 조절/삭제, 숫자 입력·키보드 편집.
- PDF 기본 사용자 좌표·회전·CropBox·UserUnit·원본 SHA-256 구조 재사용.
- JSON 설정 확인·동일 PDF 설정 검증 후 불러오기, 설정 저장 후 편집 닫기/재열기.
- 정확히 기존 활동 동의서 원본 해시일 때만 해당 양식의 기본 배치 제공.
- 가상 메타데이터만 있는 템플릿에는 원본이 없다고 표시하며 PDF 미리보기 비활성화.
- 원본 교체 시 새 버전으로 등록하고 기존 필드를 초기화한다. 동일 파일 재선택도 편집기 세션을 초기화한다.
- 템플릿 삭제는 이 탭의 목록/원본/설정을 제거한다. 과거 요청의 서류명·버전·이력은 보존한다.
- 새로고침하면 업로드 원본·이름 수정·필드 설정·삭제 상태는 사라지고 기본 가상 데이터로 돌아간다.

기존 `PdfCanvas`, 좌표/설정 모델, `validateFieldPdf`, 활동 동의서 배치, `PdfSigningPreview`를 그대로 재사용한다.
기존 편집기에 새 저장 콜백을 추가하는 대신 새 제어형 템플릿 편집 어댑터를 만들었다.
별도 참가자 연습에서 PDF를 생성해도 관리자 요청의 상태나 파일을 생성/변경하지 않는다.

### 대시보드·이력·PDF 관리 준비

- 전체 18건, 대기 3건, 완료 3건, 미발송 3건. 전체 요청은 미발송 준비 건도 포함한다.
- 대시보드는 전체 가상 이력 기준으로 고정, 표는 필터 결과/전체 수를 별도로 표시한다.
- 미발송/서명 대기/서명 완료/서명 거절/링크 만료/처리 실패 각각 표시.
- 이벤트·상태·서류별 필터, 참가자 이름 검색, 초기화, 빈 결과 처리.
- 요청 당시 서류명·버전 스냅샷을 표시하며 템플릿 이름 변경으로 과거 이력을 덮어쓰지 않는다.
- 템플릿별 서명 이력, 참가자 상세의 가상 완료일·항목별 응답·처리 타임라인.
- 응답이 없는 상태는 미기록으로 표시하고 동의 여부를 추정하지 않는다.
- 실제 완료 PDF가 전혀 없으므로 표·상세의 완료 PDF 미리보기/다운로드는 모두 disabled.
  가짜 PDF, 가짜 다운로드 주소, 가짜 서명 결과를 만들지 않는다.
- 삭제된 템플릿의 요청 이력도 조회할 수 있고 서류 필터에 ‘목록에서 삭제됨’을 표시한다.

### 문자 준비

- 조회 결과의 개별/일괄 선택, 현재 선택 대상의 개인별 문구 전환, 선택 해제.
- 필터 변경 시 선택을 비우고 현재 조회 범위의 선택만 미리보기에 사용한다.
- 이름·이벤트·서류명을 넣은 가상 문자 문구, `{개인별_서명_링크}` 자리 표시자.
- 실제 링크를 발급하지 않으며 URL을 지어내지 않는다. 링크 영역은 미발급이라고 표시한다.
- 발송·재발송·링크 발급·본인 인증 버튼은 항상 disabled이며 실행 핸들러가 없다.
- 완료/거절 대상의 재안내 적격성 판단은 실제 연동 단계의 서버 검증 대상으로 남긴다.

## 미구현 및 향후 연결

이번 상태는 UI/메모리 프로토타입이다. 목록에 실제 파일이 없으므로 완료 PDF 다운로드의 실제 전달 경로는 연결하지 않았다.
서명 요청 생성/발송/상태 변경·운영 관리자 인증·권한·실제 참가자 연결·문서 영구 저장도 구현하지 않았다.

실제 연결 시 다음 작업이 필요하다.

1. 별도 승인된 DB에서 이벤트와 `(event_id, source, application_id)`를 서버 검증하고 동명이인/다중 신청을 구분한다.
2. 가상 전용 타입/표시와 운영 모델을 분리하고 관리자 Auth/RLS, 참가자별 권한, 데이터 접근 경계를 설계한다.
3. 템플릿 불변 버전·원본 해시·페이지/필드 설정·요청 당시 스냅샷·개별 동의 응답·감사 이력을 영구 저장한다.
4. 원본/완료 PDF를 비공개 저장하고 파일 저장과 완료 확정의 실패·재시도·고아 파일 처리를 구현한다.
5. 완료 상태만으로 다운로드를 허용하지 말고 실제 파일 존재·소유권·요청 연결을 검증한 뒤 짧은 서명 URL을 제공한다.
6. 무작위 개인 토큰의 해시 저장·만료·폐기·본인 확인·재발급을 구현한다. 현재 자리 표시자를 실제 링크처럼 사용하면 안 된다.
7. 문자 업체·발신번호·비용·템플릿을 확정하고 서버에서 재발송 적격성·개인정보·수신 동의·중복 방지·결과 콜백을 검증한다.
8. 보관기간·철회·파기·PDF 다운로드 감사 정책과 실제 모바일 UX·동시성/대량 처리 검증 후 별도 승인으로 활성화한다.
