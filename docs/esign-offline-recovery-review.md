# 15단계: 외부 연결 없는 검증·장애 복구 보완

DB/Storage/SMS/OTP 접속, SQL 실행, 공통 인증·환경변수·기존 DB 변경 없음. 기존 14단계 문서는 보존했다. 모든 신규 adapter와 job 상태는 폐기 가능한 서버 메모리이며 프로세스 간 공유·재시작 복구를 제공하지 않는다.

## 구현
- source의 문자열 타입을 엄격하게 검사하고 배열/객체 강제 변환을 허용하지 않는다. 실제용 UUID는 형식 검증 후 소문자로 정규화한다. 미리보기 식별자는 명시적인 preview 모드에서만 허용한다.
- OfflineApplicantAdapter는 가상 UUID 신청자 스냅샷만 받는 비동기 reader다. revision·보관·연락처 등 입력 형태를 검증하고 복제본을 반환한다. 실제 Supabase 조회 구현이 아니다.
- inspectSigningTarget은 정규화한 키로 조회한다. 이전 상태를 브라우저에서 전달받아 신뢰하지 않는다. 승인되지 않은 참가 확정 단독·보관 미확인 정책은 계속 보류한다.
- transitionOfflineRequest는 가상 취소/만료 규칙을 시험한다. 만료는 서버 시각을 입력받아 검사하고 terminal 이력을 다시 쓰지 않는다. 재발급은 REISSUE_POLICY_HOLD로 거부한다. 기존 시연 API의 수동 만료 시험과 구분하며 운영 재발급을 활성화하지 않는다.
- OfflinePdfStore는 임시 비공개 저장소의 동작을 흉내 낸다. PDF 표식·작업 키·hash를 검사하고 덮어쓰기와 다른 내용의 동일 키 업로드를 거부한다. 실제 PDF 전체 검증·백신·암호화 검사의 대체가 아니다.
- OfflinePdfRecovery는 생성 실패/업로드 실패/확정 응답 유실을 시험한다. 생성한 바이트를 보관해 재시도에 재사용하고, 업로드 성공 후 확정 실패면 파일을 삭제하지 않는다. 같은 키+다른 payload hash는 거부한다. 동일 키 동시 실행은 큐로 직렬화한다.
- finalize 콜백 자체도 실제 DB에서 멱등적이어야 한다. 시뮬레이터는 응답 유실 시 콜백을 재호출하므로 외부 부수효과 exactly-once를 보장하지 않는다. 업로드만 된 파일을 완료본으로 제공하지 않도록 job state 확인이 필요하다.

## 검증 시나리오
복합 키·source 타입·UUID 정규화, 스냅샷 복제/변조 차단, 최신 보관/취소/연락처 판정, 만료 전 처리 거부, 취소·만료 반복 처리, 재발급 보류, 완료 이력 보존, 생성 실패→업로드 실패→성공 재시도, 파일 업로드 후 확정 응답 유실→같은 파일 재사용, 동시 동일 요청 한 번 생성·업로드·확정, 다른 payload 재사용 거부, 기존 시연 PDF 생성 중 취소 경쟁을 자동 테스트한다. 기존 중복 요청/멱등·전체 시연 테스트도 유지한다.

## 실제 연결 전에 필요한 작업·승인
1. 독립 테스트 Supabase 프로젝트·키·비용·관리자와 실제 schema/RLS 목록 승인. 운영 데이터·환경변수 복사 금지.
2. 원본 신청/관리/참여/보관 revision을 조회·검증하는 실제 adapter, 이벤트 scope와 실세션 인증 구현. 현재 사전 검사 이후 변경 경쟁은 실제 쓰기 트랜잭션에서 다시 확인해야 한다.
3. 요청·감사·멱등 원자 RPC, 정규화 payload 규약, 신청자/요청 잠금 순서 및 동시 worker CAS/lease 설계.
4. 실제 파일 저장 계약과 durable job, 재시작 후 uploaded 작업 재조회·hash 대조·확정 재시도, 취소 후 고아 파일 정리. 지금의 전역 큐·메모리 Map으로 다중 서버 문제를 해결했다고 간주하지 않는다.
5. 재발급/재서명·세대 폐기·연락처 변경 정책, 보관/파기·감사·선택 동의 문구·참가자 인증 수단 승인.
6. 기존 14단계 SQL/RLS/Storage 검토를 DB 담당자가 승인한 뒤 별도 단계에서만 migration 작성·적용한다. 이번에는 새 SQL이나 정책 적용이 없다.
