# 운영진 제공 법률 문서 반영 및 검토 기록

> 아래는 승인 전 구현 기록입니다. 이후 운영진이 두 문서를 승인하고 시행일을 **2026-10-22**로 지정했습니다. 현재 반영 결과와 남은 운영 적용 절차는 [승인·가입 활성화 기록](approval-and-signup-20261022.md)을 참고하세요. 원본 파일 및 최초 manifest는 당시의 이력으로 그대로 보존합니다.

이 폴더의 모든 문서는 **미승인 내부 검토본**입니다. 기준 원문은 이번 요청에 첨부된 운영진 작성 문서입니다. 기존 `docs/member-privacy-internal-draft.md`는 이전 조사 초안이며 이번 콘텐츠의 기준으로 사용하지 않았습니다.

## 1. 원문·번역 관리

- `privacy.ko.md`: 제공한 개인정보 처리방침 원본 파일을 바이트 그대로 복사했습니다. 16개 조항, 하위 제목, 목록, 표 4개, 내부 검토 메모 및 미정 시행일을 모두 보존했습니다.
- `terms.ko.md`: 제공한 서비스 이용약관 원본 파일을 바이트 그대로 복사했습니다. 18개 조항과 모든 항·목록·미정 시행일을 보존했습니다.
- `privacy.en.md`, `terms.en.md`: 한국어를 기준으로 작성한 영어 검토 번역입니다. 원문의 허용·의무·권리·조건과 수치·기간을 반영했습니다. 번역본에도 내부 메모와 미정 시행일을 대응시켜 보존했습니다. 법률 의미의 최종 검토·승인은 운영진에게 남아 있습니다.
- `manifest.json`: 네 파일의 SHA-256과 내부 검토 리비전을 기록합니다. 리비전은 법률 문서의 승인 버전이나 시행일이 아닙니다. `status=draft`, `approvedVersion=null`, `effectiveDate=null`입니다.

한국어 원문 두 파일의 해시는 첨부 파일과 동일합니다. 자동 테스트에서 이 해시와 번역 스냅샷 해시를 검증하며, 각 조항의 문단·하위 제목·목록 종류/번호·표 열/행 수와 모든 렌더링 텍스트를 검사합니다. 구조 일치는 번역의 법률 의미에 대한 사람의 검토를 대체하지 않습니다.

## 2. 페이지·모달·푸터

`/privacy`, `/en/privacy`, `/terms`, `/en/terms`는 공통 `MemberLegalPage`와 `MemberLegalContent`를 사용합니다. 비로그인 사용자도 접근할 수 있습니다. 현재는 각 문서의 제목과 공개 준비 안내만 표시하고 noindex를 설정합니다. 시행일을 임의로 넣지 않습니다.

승인 문서 모델은 제목·서문·조항·하위 제목·문단·굵은 표시·번호 목록·일반 목록·표를 지원합니다. 표는 의미 있는 HTML 테이블과 가로 스크롤 영역으로 렌더링하고, 목차는 각 조항의 안정적인 `article-N` 앵커로 이동합니다. 임의 HTML을 실행하지 않습니다.

가입 화면은 같은 문서 객체를 기존 공통 모달에 전달합니다. 문서별로 독립적으로 전달되므로 개인정보 처리방침과 약관을 섞지 않습니다. 모달 내부 스크롤, ESC/X/외부 클릭 닫기, 초기 제목 포커스와 원래 버튼 포커스 복원, 배경 스크롤 잠금 및 입력값 보존을 유지합니다. 영어 명칭은 Terms of Service로 통일했습니다.

공통 푸터에 개인정보 처리방침/이용약관을 연결했습니다. 영어에서는 Privacy Policy/Terms of Service가 각 `/en/` 경로로 연결됩니다. `/privacy`·`/terms`도 기존 명시적 언어 선택과 쿠키 처리 대상에 추가했습니다.

## 3. 승인과 가입 차단의 분리

`src/lib/member-legal.ts`의 `memberDocumentApprovals`는 privacy와 terms를 각각 관리합니다. 두 항목 모두 `status: "draft", document: null`입니다. `getPublishedMemberDocument()`는 명시적 approved 상태, 문서 버전과 유효한 시행일을 확인하며 미정 시행일·내부 검토 메모가 남은 문서는 추가로 차단합니다. 이 검사는 법률상 충족 여부를 판정하는 기능이 아닙니다.

이 폴더는 앱의 import 대상이나 public 자산이 아닙니다. 현재 원문·번역 전문을 앱에 삽입하지 않았고, 공개 준비 안내를 전문처럼 꾸미지 않았습니다. 빌드 JS에서 원문 고유 문장들이 포함되지 않은 것도 확인했습니다.

기존 `publishedMemberLegal=null`과 서버 전용 `memberRegistrationPolicy=null`은 그대로입니다. 문서 하나 또는 두 개를 공개해도 가입 준비가 자동 완료되지 않습니다. 실제 가입 활성화는 수집 고지·필요한 동의·저장 증빙·Auth·DB 준비를 별도로 검토하는 작업입니다. 수집·이용 동의나 선택정보 동의를 임의로 추가하지 않았습니다.

## 5. 실제 공개를 위한 후속 작업

1. 운영진이 위 항목과 양 언어의 의미를 검토하고, 각 문서를 개별 승인합니다. 원문 수정이 필요한 경우 승인된 새 원문을 받아 새 리비전으로 보존합니다. 이번 초안을 자동 편집하거나 내부 메모만 잘라내지 않습니다.
2. 승인된 KO/EN 원문에 승인 버전·시행일을 부여합니다. 순수 변환 도구 `prepareMemberLegalDocument(ko, en, version, effectiveDate)`는 문서 모델 준비에 사용할 수 있습니다. 이 함수는 승인이나 공개 상태를 바꾸지 않습니다.
3. 별도 코드 작업에서 승인된 정적 문서 스냅샷을 준비하고 해당 문서의 approval에만 연결합니다. 초안을 import하거나 서버에서 매 요청마다 docs를 읽는 방식은 사용하지 않습니다. 원문과 번역의 전체 내용을 다시 비교합니다. 준비 안내는 해당 문서에 한해 전문으로 바뀝니다.
4. 전문의 목차·긴 문서 스크롤·표·모바일·모달 및 공개 메타데이터를 재검증한 뒤 별도 배포 승인을 진행합니다. 두 문서의 공개 여부와 회원가입 활성화는 별개입니다.

## 7. 검증 결과

- 관련 자동 테스트: 90/90 통과. 문서 테스트 8개, 기존 가입·로그인·게시판 테스트 포함.
- `npm run lint`: 오류 0, 기존 경고 3개(suggestions.ts 2개, external-account-people-db.mjs 1개).
- `node node_modules/typescript/bin/tsc --noEmit --incremental false`: 통과.
- `npm run build`: 성공. 네 법률 경로 모두 생성. 기존 Supabase SDK Node.js 20 지원 종료 예정 경고가 남아 있습니다.
- 로컬 프로덕션 브라우저: 비로그인으로 네 경로 접근, 실제 한영 전환, 양 언어 푸터 링크, 390px 모바일 한글 약관/개인정보 모달과 영어 약관 모달, 준비 안내만 표시, ESC 닫기·제목/트리거 포커스·스크롤 잠금·닉네임 입력값 보존 확인.
- 전문은 미승인이므로 실제 공개 페이지에 임시 삽입하지 않았습니다. 전문 목차의 href/ID 대응, 표와 모든 텍스트의 보존·양 언어 대응은 정적 렌더링 자동 테스트로 확인했습니다. 법률 의미의 최종 승인을 대신하지 않습니다.

현재 브랜치 `feat/website-yukyung2`를 유지했습니다. 새 브랜치·commit·push·자동 배포·운영 Supabase 변경·SQL 실행·회원/게시물 데이터 변경은 하지 않았습니다.
