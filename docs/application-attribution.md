# 신청자관리와 유입경로

사이드바 `/admin/recruitment`는 전체 이벤트 신청자 목록입니다. 이벤트·선발·입금·유입경로·매체 등으로 필터링하며 기존 이벤트별 목록·상세 수정·참여 이력 링크도 유지합니다.

전체 목록과 이벤트별 목록 모두 선발·입금 상태만 목록의 선택 상자에서 직접 저장합니다. 이름·연락처·출생연도·국적·내부 메모 등은 상세·수정 버튼의 대화상자에서 기존 관리자 저장 함수를 사용해 수정합니다. revision 충돌 시 저장을 중단합니다. UTM과 접수일은 목록에서 읽기 전용입니다.

전체 신청자관리는 여러 이벤트의 신청 내역과 유입경로 비교·검색을 담당하고, 이벤트를 선택한 수동 추가 양식을 제공합니다. 저장 후 선택한 이벤트로 필터한 전체 목록으로 돌아갈 수 있습니다. 이벤트별 신청자·운영은 이벤트를 고정하고 전체·접수·검토·합격·대기·미입금 집계 및 빠른 필터와 개인별 참여·출석 기록 링크를 제공합니다. 집계는 페이지나 검색 조건과 무관한 해당 이벤트 전체이며 조회 실패를 0으로 표시하지 않습니다. 실제 참석 집계는 참여이력관리에서 확인합니다. 이벤트 개요·대시보드의 신청자 버튼은 이벤트별 목록으로 연결합니다.

이전 작업의 017 접수일 정정 SQL은 DB에 추가되었으나 가상 DB 실행 검증은 SQL 편집기 입력 오류로 미완료입니다. 현재 화면에서는 접수일 정정 기능을 노출하지 않습니다. PR #28 납부·환불 DB와 실제 문자 발송의 보류는 유지합니다.

채널 값: naver(네이버), everytime(에브리타임), daangn(당근), meta(메타), instagram(인스타그램).
표준 `utm_source`를 사용하고, 공개 신청 URL의 `source`도 호환 입력으로 받습니다. `utm_medium`, `utm_campaign`은 선택입니다. 태그 없는 기존 신청은 미확인이며 실제 플랫폼 방문을 인증하거나 방문자 수를 측정하지 않습니다.

관리 화면의 링크 생성기에 실제 모집 페이지 주소를 입력해 채널별 주소를 복사합니다. 외부 모집 페이지는 신청 요청에 동일한 태그를 전달해야 합니다. 현재 코드에서 저장 연결된 공개 폼은 할로윈의 EventRegistrationForm입니다. 9기 폼은 기존처럼 제출 비활성입니다. 언어 전환·외부 폼 등에서 쿼리가 유실되지 않도록 배포할 최종 신청 URL로 확인해야 합니다.

DB 016은 기존 011 이후 적용 가능하며 보류된 참가비 012~015에 의존하지 않습니다. 기존 신청자 뷰를 교체하지 않고 별도 관리자 조회 뷰를 만들었습니다. 추후 납부·환불 뷰 변경 시에도 유입 뷰가 의존하므로 DROP/CASCADE 없이 호환성을 검토해야 합니다. PR #28 보류 유지.

`submit_event_registration_attributed`는 기존 신청 함수의 마감·동의·중복·정원 검사를 그대로 실행하고 같은 트랜잭션에서 태그를 기록합니다. 원래 함수를 변경하지 않았으며 재시도는 최초 태그를 덮어쓰지 않습니다. 직접 추가한 신청에는 채널을 추정하지 않습니다. 태그 저장 테이블은 관리자 조회만 허용하고 직접 쓰기는 차단합니다.

검증: 채널 URL·별칭·미확인·길이·안전한 URL 테스트 3개 및 기존 신청자 검증 3개 통과. Supabase SQL 가상 저장·조회·재시도 보존·권한·비관리자 RLS 검사를 통과했고 테스트 레코드는 롤백했습니다. DB 테스트는 실제 관리자 로그인/API 전체 흐름을 대체하지 않으며 배포 후 별도 브라우저 검증을 기록합니다.
