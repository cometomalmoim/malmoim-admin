# A조 할로윈 이벤트 등록·날짜 편집·디자인

2026-10-15

## 적용
- 실제 `halloween-2026` 이벤트를 2026 말모임 할로윈 파티로 등록했다. 일시 10/31 19:00~11/1 00:00 KST, 연신내 하이브. 참가비 추후 안내, 정원 미정, 모집 시작·마감 NULL, draft/접수 비활성.
- SQL007 적용 성공. 기존 데이터 유지, 초안만 모집 기간 미정 허용, 공개·접수 상태에는 유효한 기간 필수.
- 관리자 정보 수정에서 모집 시작·마감을 설정·변경하거나 모두 비울 수 있다. 한쪽만 입력, 역전, 행사 이후 마감은 거절.
- 화면 스타일 기본/할로윈 선택. 해당 이벤트 카드·상세에만 적용. 기존 9기와 관리자 공통 디자인은 유지.
- 할로윈 카드·상세에서 기존 한·영 공개 랜딩으로 이동 가능. 실제 신청 저장·접수 활성화는 포함하지 않는다.

## 1. 문제사항
모집 기간이 미정이어도 초안 단계에서 필수 날짜를 입력해야 했다. 할로윈 행사는 일반 카드와 구분되지 않았고 기존 공개 랜딩 연결이 필요했다.

## 2. 개선 경험
실제 할로윈 이벤트 등록, 모집 기간 추후 편집, 이벤트별 테마 및 공개 랜딩 링크를 연결했다. 사용자 기여는 요구와 적용 범위 결정이며 기존 랜딩 구현은 이번 개인 신규 성과로 포함하지 않는다.

## 3. 과정
기존 DB·화면 확인→모집 기간 미정 모델과 DB 제약 설계→할로윈 카드/상세 구현→초안 등록→테스트·빌드→고정 브랜치와 PR 배포.

## 4. 수치
입력 자동 테스트 5/5 통과. lint·운영 빌드 통과. 업무 시간·반복 입력 횟수 개선은 미측정이며 수치로 만들지 않는다. 실제 화면 검증은 배포 후 별도로 확인한다.

## 5. 어려움과 해결
임의 날짜를 넣는 대신 초안의 미정 날짜를 NULL로 저장했다. 실제 게시·접수 시에는 DB 제약으로 모집 기간이 필요하도록 했다. 테마를 제목 문자열로 추측하지 않고 visual_theme 필드로 관리해 제목을 바꿔도 디자인을 유지한다.

## 6. AI 활용
사용자 피드백을 날짜 미정과 이벤트별 디자인이라는 구체적인 요구로 바꾸고, UI·검증·DB 조건을 함께 수정했다.

## 7. 포트폴리오
“행사 준비 단계에서 모집 기간을 나중에 결정하는 운영 흐름을 반영해 초안 저장과 기간 편집을 개선했습니다. AI를 활용해 할로윈 이벤트의 카드·상세 디자인과 기존 랜딩 연결도 구현했습니다.”

## 8. 자소서
“운영진이 미확정 날짜를 임의 입력해야 하는 문제를 확인했습니다. 초안과 실제 접수 상태의 조건을 구분해 설계하고, 날짜 입력 검증과 DB 제약을 함께 보완했습니다. 이벤트별 디자인 범위도 사용자와 확인하며 요구를 구체화했습니다.”
