# 10단계: 관리자 → 참가자 → 완료 PDF 개발 시연

운영 기능이 아니다. 실제 DB/Storage/SMS/OTP/개인정보 연결 없음. 개발 환경의 localhost/127.0.0.1에서만 API 호출 가능. production에서 관리자/참가자 API POST는 404, 참가자 페이지·모바일 프레임도 notFound다. 고정 테스트 관리자 헤더는 실제 인증이 아니다.

## 실행

원본 저장소의 운영 환경변수를 사용하지 않는다. 검증에 사용한 환경변수 없는 복사본 `work/pdf-fields-check`에서:

```sh
NEXT_TELEMETRY_DISABLED=1 WATCHPACK_POLLING=true npm run dev -- --webpack --hostname 127.0.0.1 --port 3187
```

관리자: http://127.0.0.1:3187/preview/document-admin

1. ‘합격자 요청 준비 · 6단계’ 탭 → ‘테스트 관리자 역할 사용’ 선택.
2. 이벤트·서류 선택, 가상 대상 01 또는 11 선택 → 최종 확인 → 서버 검증 후 메모리 목록 반영.
3. 요청 행에서 ‘개발 테스트 링크 준비’. 링크와 `DEMO-…` 가상 확인 코드가 표시된다. 실제 OTP나 실명 인증이 아니다.
4. 참가자 링크 `/preview/sign/<임의값>` 열기 → 관리자 화면의 가상 코드를 입력.
5. 테스트 PDF 원문 확인 → 필수 항목 세 개 개별 확인 → 촬영·홍보는 동의/거절 개별 선택 → 테스트 모양으로 서명.
6. 서명 지우기·재작성 또는 최종 확인에서 다시 수정 가능. 이름은 해당 요청의 가상 이름으로 고정, 날짜는 서버 접수 시각의 한국 날짜.
7. 최종 확인 체크 후 제출. 서버가 원본/동의/서명/요청 상태를 검증하고 PDF 생성 후 다시 상태를 확인한다.
8. 참가자 완료 PDF 다운로드. 관리자는 서버 목록/참가자 단계 재조회 후 ‘서버 메모리 완료 PDF 확인’으로 미리보기/다운로드.

모바일 폭 시연: 참가자 URL 뒤에 `/mobile`을 붙이면 390px iframe으로 표시한다. 실제 휴대폰/Safari 검증이나 외부 접근을 제공하는 기능은 아니다.

## 문서와 저장 위치

- 기존 업로드 PDF 편집/3단계 브라우저 서명 기능은 유지한다.
- 시연용 서버에 실제 말모임 PDF 원본이 없으므로 모든 시연 요청은 `말모임 개발 전용 테스트 동의서`를 사용한다. 실제 서류·운영 버전의 완료본으로 대체하지 않는다. 원본/완료 PDF에 테스트 문서임을 명시한다.
- `esign-demo-pdf.ts`: 기존 동의 항목·서명 검증·서명 SVG 경로·PDF 좌표 구조를 재사용한다. 서버 fontkit/pdf-lib와 저장소 한글 폰트로 생성. 한 번 작성한 서명 두 곳 적용. 선택 거절은 완료 기록 페이지에 명시한다.
- `esign-demo-flow.ts`: 요청별 개발 링크·가상 확인 코드·서명 세션·원본·완료 PDF·멱등 접수 결과를 메모리에 보관한다.
- `esign-demo-state.ts`: 관리자와 참가자 Next route bundle 간 공유되는 단일 Node 프로세스 registry. 9단계 요청 repository/service를 그대로 연결한다.
- 브라우저에는 탭 식별자·요청 전용 개발 세션을 sessionStorage로 유지하고, PDF 보기용 임시 Blob URL을 만든다. 실제 PDF 파일은 DB/Storage/공개 폴더에 저장하지 않는다. 다운로드하면 사용자의 로컬 다운로드 폴더에 저장된다.

## 권한·상태와 실패

가상 확인 전에는 참가자 이름/문서를 반환하지 않는다. 세션은 요청별이며 다른 링크의 세션으로 원문·제출·PDF를 열 수 없다. 개발 링크를 아는 것만으로 확인을 통과하지는 않지만, 관리자 코드까지 가진 사람을 구별할 실제 본인 인증은 아니다. 실제 개인정보 사용 금지.

요청 pending과 별도로 waiting → verified → signing → completed 단계를 표시한다. 링크/제출은 직렬화하고 요청 만료·취소·자격 상실을 원문/제출 시 확인한다. PDF 생성 중 취소되면 완료 확정 트랜잭션에서 거절한다. 동일 멱등 키+동일 제출은 기존 완료 결과 반환, 다른 제출은 거부. 완료된 PDF를 새로 덮어쓰지 않는다. PDF 실패 시 완료 처리하지 않으며 재시도 가능.

기존 ‘서버 가상 완료’ 시험은 PDF를 생성하지 않는다. 그런 기록에 완료 PDF를 임의로 붙이지 않는다. 관리자 PDF 요청은 실제 메모리 PDF가 없으면 PDF_NOT_READY로 거절한다.

## 새로고침·재시작 제한

같은 관리자 탭 새로고침 후 테스트 역할을 다시 선택하면 요청 목록을 재조회한다. 참가자도 ‘이 탭의 인증·서명 상태 다시 조회’로 30분 개발 세션과 완료 PDF를 재조회한다. 새 탭에서는 코드로 다시 확인해야 하며 새 확인은 이전 개발 세션을 교체한다.

서버 재시작 시 요청·링크·개발 세션·PDF 모두 사라진다. 프로세스 전역 registry는 일부 HMR에서 유지될 수 있으나 보장하지 않는다. 다중 프로세스 간 공유 없음. 영구 저장/감사 증명/실제 인증이 아니다. 모바일 실기기·SMS·DB 연동은 별도 단계다.
