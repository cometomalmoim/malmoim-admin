## 1. 대상별 콘텐츠와 화면

- 한국인용: ‘영어로 대화하고, 세계와 친구가 되는 시간’. 실제 영어 사용 기회, 서로 한국어를 알려주는 경험, 혼자 참여하기에 대한 안내를 중심으로 구성.
- 외국인용: ‘Practice Korean. Make Korean friends.’ 한국어 연습, 한국인과의 교류, 한국에서 나누는 일상을 중심으로 별도 카피 구성. 국제 참가자가 활동지로 영어 대화를 이끄는 기존 운영 방식도 유지.
- 공감 → 커뮤니티 소개 → 프로그램 → 실제 활동 → 추천 대상 → 모집 정보·포스터·지도 → 신청 절차·FAQ → 문의 → 기존 신청 폼 순서.
- 기존 로고, 노란 신청 버튼, 청록 계열을 유지하고 따뜻한 크림색 바탕과 실제 사진 중심으로 개선. 장식용 낙엽 애니메이션은 새 랜딩에서 사용하지 않음.
- 모바일 하단 신청 버튼은 신청 폼이 보이거나 폼에 초점이 있을 때 숨김. 키보드 포커스와 reduced-motion 지원 유지.

## 2. 사진 선정

전달된 사진의 장면을 확인하고 8장만 사용. 중복 첨부, 비슷한 단체사진, 수료증 실명 등이 눈에 띄는 사진은 제외. 사진만 보고 인물의 국적이나 관계를 단정하지 않음.

## 3. 주소·SEO·추적

- `/season9`와 `/season9/ko`: 동일한 한국인용 공통 컴포넌트. 언어 선택 화면 제거, 강제 브라우저 언어 리다이렉트 없음.
- `/season9/en`: 외국인용 영어 콘텐츠. 헤더에서 바로 한·영 전환.
- 언어 전환에 UTM 5종과 현재 앵커 유지. 다른 개인정보성 쿼리는 언어 링크에 복사하지 않음.
- 기존 `/season9/apply`, `/season9/en/apply`, `/season9/apply/en`의 해당 언어 하단 폼 리다이렉트 유지.
- 한국어 canonical은 `/season9`로 통일, 영어 canonical `/season9/en`. hreflang, Open Graph, Twitter 이미지·문구 갱신.
- 기존 Meta Pixel ID, 초기화/중복 방지와 PageView 보존. 실제 DB accepted=true에만 CompleteRegistration receipt 생성. 새 한국어 root 경로를 전환 허용 목록에 추가. 성별 등 신청 정보는 전환 receipt에 포함하지 않음. 신청 버튼 클릭을 신청 완료로 처리하지 않음.
- 기존 `public_event_reviews`는 published + publication_confirmed 조건을 통과한 후기만 반환함을 소스에서 확인. 이 API와 후기 UI를 유지하고 가상 후기/통계를 새로 만들지 않음.

## 4. 성별 저장·관리자

- 현재 사용 중인 한·영 `CompactApplication` 양쪽에 선택 항목 추가: male / female / self_describe / prefer_not_to_say.
- 직접 입력을 선택할 때만 짧은 입력란(최대 35자)을 표시. 빈 선택과 빈 직접 입력은 null로 처리하여 신청을 막지 않음. 다른 선택으로 바꾸면 숨겨진 직접 입력은 제출하지 않음.
- 기존 nullable `event_applications.gender` 컬럼 재사용. male, female, prefer_not_to_say 또는 `self_describe:<입력>`로 저장. 스키마 컬럼 추가·기존 행 변환 없음.
- 기존 관리자 조회 뷰가 gender를 이미 가져오므로 그대로 활용. 상세·수정의 성별 표시와 신청서 원문 응답에서 일관된 한국어 레이블 표시. 기존 null·과거 한영 문자열·할로윈 other 데이터도 호환.
- 활성 신청자 관리에 CSV/엑셀 내보내기 기능은 발견되지 않아 새 내보내기는 추가하지 않음.
- 레거시 `InstantApplication`은 현재 공개 신청 경로에서 사용되지 않음. 현재 공개 경로는 모두 간단 신청 폼으로 연결되므로, 사용하지 않는 레거시 API의 필수 필드 규칙은 변경하지 않음.

## 5. 검토용 DB 변경 및 적용 순서

`supabase/drafts/20261027_season9_optional_gender_v2.sql` **미적용**.

- 기존 v1 저장 함수는 그대로 두고 v2 저장 함수와 v2 접수 상태 함수만 추가.
- 개인정보 안내에 선택 성별 수집을 명시하고 새 notice version·스냅샷을 저장. 기존 참가비·환불·사진 필수 동의 의미는 유지.
- 기존 모집 게이트, 마감·보관 상태, phone 재신청 허용, Instagram 중복 금지, submission_id 재시도, rate limit, 트리거·RLS 유지.
- 앱은 v2 접수 상태 함수를 확인하므로 마이그레이션이 없는 환경에서는 폼을 비활성화한다. 성별을 조용히 버리고 성공으로 표시하지 않도록 한 처리.
- 별도 승인 후 **마이그레이션 검토·적용 → 상태/권한 확인 → 해당 프런트 배포 → 운영 읽기 검증** 순서 필요. 모집 스위치를 켜거나 실제 신청·문자를 테스트로 생성하지 않을 것.
- 앱 롤백 시 기존 프런트는 v1 함수로 계속 동작할 수 있음. v2를 즉시 삭제하면 열린 새 탭에 영향을 줄 수 있으므로 별도 검토 필요.

## 6. 검증과 제한

- 변경 TS/TSX ESLint, TypeScript, Next production build 통과.
- 관련 Node 테스트 26개 통과: 신규/기존, 성별 null·선택·직접 입력·길이 제한·숨김 데이터 무시, 언어 링크 UTM/앵커, 관리자 레이블, 서버 성공·실패 전환 및 개인정보 제외, 레거시 필드 회귀.
- 임시 PGlite PostgreSQL에서 마이그레이션 실행 후 anon 역할로 저장 검증: 각 성별 값·null, v1 호환, 동일 ID 재시도·변경 거부, phone 재신청, Instagram 중복, 필수 동의, 마감·보관 게이트, 익명 조회 금지, 저장된 UTM·안내 스냅샷 확인. 운영 Supabase DB에는 쓰지 않음.
- 브라우저: 390×844 모바일과 1440×1000 데스크톱 한·영 화면 확인, 가로 넘침 없음. 언어 전환 후 실제 URL의 UTM·앵커 유지 확인. 신청 앵커/모바일 하단 버튼 숨김 확인.
- 한·영 GenderField를 서버 액션 없는 임시 로컬 페이지에 렌더링해 직접 입력 표시·숨김과 optional 제어 확인. 검증 페이지는 삭제했고 최종 빌드에 포함되지 않음.
- 정적 생성된 세 주소 HTML에 canonical·h1 1개·성별·application 앵커와 언어 선택 화면 제거 확인.
- v2 운영 마이그레이션은 미적용이므로 실제 전체 브라우저 접수 성공·운영 관리자 실데이터 표시는 미검증. 로컬 신청 폼의 ‘접수 상태 확인 불가’는 이 준비 상태를 반영하며 실제 사이트에는 영향 없음.
- 기존 Next.js 16.4.0의 보안 업그레이드 안내가 빌드에 출력됨. 이번 변경에서 의존성 버전은 변경하지 않았음. 배포 전 별도 보안 업그레이드 검토 권장.

## 7. 운영 확인 필요

1. 목요일/토요일 전체 150분 중 45+45+40=130분을 제외한 나머지 20분 구성. 임의로 휴식·준비 시간이라 적지 않음.
2. 외국인 참가자의 원어민 제한 여부, 영어 최소 기준, 영어 대화를 주도하는 범위, 별도 준비물/수업 준비 필요 여부. 기존 활동지·리더 방식만 설명하고 미확인 기준은 넣지 않음.
3. 인스타그램 연락처만 제출한 사람에게 결과·납부를 어떤 경로로 안내할지. 기존 ‘문자 안내’ 운영 문구를 유지했으므로 실제 운영 확인 필요.
4. 활동 시작 전 구체적 환불 기준. 기존 ‘시작 후 환불 불가’만 표시하고 미확인 세부 규정은 만들지 않음.
5. 선택 성별 수집 안내·목적 및 v2 개인정보 스냅샷에 대한 운영 검토 후 마이그레이션/배포 승인 필요.
