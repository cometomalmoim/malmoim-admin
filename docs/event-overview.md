# A조 이벤트 개요 공통 틀

2026-10-15

## 화면과 분담
- 사이드바 이벤트 관리→이벤트 선택→개요. 별도 전역 개요 메뉴는 만들지 않는다.
- 기존 이벤트별 overview URL과 관리자 보호 경계를 유지한다. 할로윈 테마는 소개 영역에 유지한다.
- 기본 정보, 모집 기간, 참가비 안내, 등록 상태, 접수 설정, DB 신청 건수를 표시한다.
- 정보 수정·기간 수정·안내 수정은 기존 편집 화면으로 연결한다. 입력·저장 기능을 중복 구현하지 않는다.
- 알려진 9기/할로윈 한영 랜딩을 표시하며 페이지 공개와 실제 접수 상태를 구분한다.
- 실제 연결: 신청자 목록, 이벤트 자료실. 준비 중: 참여자·출석, 문자, 수료증, 회차 관리. 미구현 기능에 가짜 성공·불능 URL을 만들지 않는다.
- 참가비는 기존 fee_notice 표시/수정 연결만 담당한다. 금액 구조·결제·납부/환불은 담당자 기능에서 확장한다.
- DB 변경·신청 접수 활성화·상태 변경·선발·출석 등은 포함하지 않는다.

## 1. 문제사항
기존 상세는 긴 정보 목록으로만 구성돼 일정·모집·참가비·신청자 및 다음 작업 위치를 한눈에 확인하기 어려웠다.

## 2. 개선 경험
이벤트별 개요를 운영 현황과 기본 정보, 모집·참가비 안내, 관리 바로가기로 나눴다. 기존 담당 기능을 연결하는 공통 틀에 집중했다.

## 3. 진행 과정
사용자와 사이드바/이벤트별 구조 및 역할 분담 확정→기존 조회·편집 재사용→실제 신청 건수 조회→일정/모집/비용 영역 분리→검사와 배포 후 확인.

## 4. 측정
기존/개선 후 업무 시간과 이동 횟수는 미측정. lint·운영 빌드와 실제 이벤트 화면·모바일 검증을 근거로 기록한다. 신청 건수는 DB 조회 결과이며 선발·참가 확정 인원과 구분한다. 조회 실패를 0건으로 표시하지 않는다.

## 5. 어려움과 해결
안내 페이지가 공개돼 있어도 신청 접수는 비활성일 수 있다. 페이지 링크와 접수 설정을 분리해 표시했다. 미구현 기능을 클릭 가능한 링크로 만들면 오류 화면으로 이동하므로 준비 중 표시로 구분했다.

## 6. AI 활용
요구사항과 팀 역할을 구체적인 정보 배치와 연결 경계로 정리하고, 실제 데이터 조회와 표시 조건을 검토했다.

## 7. 포트폴리오
“팀원별 기능 개발을 연결하는 이벤트 개요 화면을 설계했습니다. 실제 DB 정보와 신청 건수를 표시하고 모집·참가비·신청자 관리로 이동하는 구조를 구성했습니다.”

## 8. 자소서
“이벤트 운영 화면의 큰 틀을 맡아 공통 정보와 담당 기능의 경계를 정리했습니다. 사용자와 탐색 구조를 확인하고 기존 기능을 재사용해 중복 구현을 줄였습니다. 미구현 기능과 접수 상태를 구분해 운영자가 화면을 오해하지 않도록 구성했습니다.”
