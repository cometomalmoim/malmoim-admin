## 로딩

설치된 Next.js의 loading 및 layouts-and-pages 문서를 읽고 기존 페이지 내부 Suspense 경계를 재사용했다. Cache Components/스트리밍 구조를 유지하면서 8개 경로의 텍스트 fallback을 교체했다. 상위 목록용 loading.tsx를 추가하지 않아 상세·작성·수정에서 목록 스켈레톤이 나타나는 중첩을 피했다.

PublicFrame과 헤더는 기존 공통 레이아웃에만 남아 있다. 스켈레톤은 main 콘텐츠만 제공한다. 목록 제목, 탭, 검색 필터, 글쓰기, 목록, 핫 키워드의 실제 배치를 따른다. 상세는 게시글/댓글, 작성·수정은 입력 필드를 표현한다. 가짜 게시글이나 가짜 키워드는 추가하지 않았다.

스켈레톤의 공간은 즉시 확보하고 120ms 후 짧게 나타나도록 해 매우 짧은 응답의 깜빡임을 줄였다. 절제된 opacity 애니메이션만 사용하고 prefers-reduced-motion에서는 모두 해제한다. aria-busy와 role=status를 제공하고 장식용 막대는 화면 낭독기에서 제외한다. 모바일 로딩은 키워드를 생략하고 목록 중심으로 구성한다. 실제 데이터의 글 수와 본문 길이를 미리 알 수 없으므로 완료 시 높이 변화가 완전히 없어지지는 않는다.

로딩은 데이터 조회가 끝나면 기존 정상/빈 목록/DB 오류/로그인 필요/접근 제한/없는 게시글 화면으로 교체된다. 조회 함수, 오류 분기, notFound 처리는 변경하지 않았다.

## 상세와 댓글

밝은 회색 배경 위 중앙 최대 1120px의 게시글·댓글 영역을 배치했다. 작은 모서리와 얇은 구분선을 사용하며 그림자는 없다. 목록 복귀, 청록색 카테고리, 큰 제목, 작성자 별칭, 작성·수정 시각, 조회·댓글 수 순서로 정리했다. 별칭과 원문은 기존 데이터 그대로이며 줄바꿈과 긴 URL의 줄바꿈 처리를 유지한다.

본문 아래 왼쪽에 테두리 수정/노란 삭제 버튼, 오른쪽에 신고를 배치한다. 기존 can_edit와 인증 조건 및 삭제 확인을 유지한다. 액션이 없는 경우 빈 액션 영역을 만들지 않는다. 관리자 공지 수정, 숨김·복구·고정·신고 처리 폼과 서버 권한 검증도 유지한다.

댓글은 제목/실제 수/목록/빈 상태/입력을 구분한다. 댓글 검색 결과가 없는 상태는 일반 빈 댓글 안내와 구분한다. 작성란에는 안내문과 노란 등록 버튼을 적용했다. 기존 제어 입력, pending 상태, 오류 메시지, nonce, 제출 중 비활성화 로직을 유지해 오류 시 입력 보존과 중복 제출 방지가 계속 동작한다. 댓글 페이지가 하나이면 페이지 표시를 숨기고, 여러 페이지 또는 범위를 벗어난 페이지에서는 이동 링크를 유지한다.

모바일에서는 작성자와 메타 정보가 줄바꿈되고 댓글 입력 아래에 전체 너비 등록 버튼을 표시한다. 키보드 포커스, label, 최소 버튼 높이를 유지한다.

## 시안과의 차이 / 남은 검증

이미지를 배경으로 사용하지 않고 실제 컴포넌트/CSS로 구현했다. 목록 제목과 필터 위치는 기존 서비스와 로딩 전후 일관성을 위해 유지했다. 시안의 아바타 목록과 두 번째 사이드 패널은 실제 목록 구조에 없으므로 추가하지 않았다. 댓글 입력 옆 장식용 아바타와 액션 장식 아이콘은 단순화했다. 비회원은 시안의 작성자 버튼/댓글 입력 대신 기존 로그인 안내가 표시된다.

실제 인증된 작성자와 관리자 계정으로 브라우저에서 댓글 저장·실패 후 입력 유지, 삭제 확인 취소, 숨김·복구·고정·신고 처리까지 확인하는 검증이 남아 있다. 원격 DB를 변경하지 않는 범위의 이번 작업에서는 실행하지 않았다. 실측 CLS나 느린 네트워크별 로딩 시간은 측정하지 않았다.
