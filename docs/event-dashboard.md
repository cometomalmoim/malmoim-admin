# A조 이벤트 대시보드 연결

2026-10-15

## 범위와 팀 분담
이번 작업은 관리자 공통 대시보드의 실제 이벤트 조회·정렬·기존 화면 연결만 담당한다. 데이터 저장/상태 변경이나 별도 이벤트 관리 페이지를 중복 구현하지 않는다.

- 등록된 이벤트 수, 시작 전 이벤트 수, 시작일 미정 이벤트 수를 실제 DB 조회로 표시.
- 예정된 이벤트: starts_at >= 조회 시각, 가까운 시작일 순, 같은 시각은 id 순, 최대 5개. 초안 포함, 이미 시작한 행사와 시작일 NULL 제외. 모집 마감은 행사 종료와 별개이므로 미래 행사는 closed여도 포함.
- 이벤트 목록: 최근 등록 순 최대 6개. 전체 이벤트 관리로 이동 가능. 일시 미정도 표시.
- 시간 표시는 한국시간. 조회 오류와 실제 0건을 구분한다. 페이지 및 조회 함수에서 관리자 검사.
- 기존 /admin/events/[slug]/overview·edit·applicants로 연결.
- 공개 홈페이지·기존 이벤트 관리 목록·자료실·모집 페이지는 수정하지 않는다. 개발 preview는 기존 구성 유지.

친구 담당 기능 연결 지점: 참가비/결제는 이벤트 상세, 모집 빌더는 모집 페이지, 선발은 신청자, 출석은 회차별 운영, 문자·수료증은 기존 예약 메뉴에서 확장한다. 이번에는 검색·필터·상태 변경·회차 입력·신규 메뉴·결제·신청 저장 등을 추가하지 않는다.

## 1. 문제사항
DB에 이벤트가 등록돼 있어도 대시보드는 빈 안내와 미연결 수치를 표시했다. 운영자가 다가오는 행사를 확인하려면 이벤트 관리로 이동해야 했다.

## 2. 개선 경험
이벤트 대시보드에서 실제 목록과 가까운 일정, 날짜 미정 항목 수를 확인하고 기존 관리 화면으로 이동할 수 있게 했다. 다른 담당자의 참가비·운영 기능과 구분해 조회 중심의 큰 틀만 연결했다.

## 3. 과정
기존 계획·공통 메뉴·데이터 조회 조사→역할 중복 배제→관리자 보호 조회→예정일 오름차순/최근 등록 목록 분리→빌드·운영 확인.

## 4. 측정
업무 시간·이동 횟수의 개선 전후 값은 미측정이다. lint·운영 빌드 및 실제 목록·정렬·모바일 확인 결과를 근거로 남기며 운영 성과를 임의로 계산하지 않는다.

## 5. 어려움과 해결
모집 마감 상태를 행사 종료로 해석하면 시작 전 행사가 누락된다. 예정 여부는 모집 상태 대신 실제 시작일로 판정했다. 시작일이 없는 9기 등 기존 이벤트는 목록에 유지하고 예정 일정에서는 제외해 잘못된 날짜를 만들지 않는다.

## 6. AI 활용
사용자의 업무 분담과 요청을 실제 조회·정렬·바로가기라는 범위로 정리하고 기존 기능에 연결했다. 다른 사람의 기능 구현을 이번 개인 성과로 포함하지 않는다.

## 7. 포트폴리오
“분담된 행사 운영 기능을 중복 구현하지 않도록 조회 중심의 대시보드를 설계했습니다. 실제 이벤트 목록을 연결하고 다가오는 행사를 시작일이 가까운 순서로 표시했습니다.”

## 8. 자소서
“팀원이 담당한 기능과 겹치지 않는 운영 화면의 큰 틀을 맡았습니다. 이벤트 정보의 입력과 운영 처리는 기존 화면에 두고 대시보드에서는 현황과 일정에 집중했습니다. 모집 마감과 행사 시작을 구분해 목록을 설계하며 역할 분담과 업무 규칙의 중요성을 경험했습니다.”
