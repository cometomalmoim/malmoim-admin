# 회원 탈퇴 및 게시물 익명화 설계 — 실행 전 검토용

현재 자동 탈퇴 RPC/API/버튼은 추가하지 않았습니다. 계정 삭제와 개인정보 삭제를 완료했다고 표시하는 코드도 없습니다. 아래 정책과 데이터 관계를 확인한 뒤 별도 마이그레이션으로 구현해야 합니다.

확정 정책은 계정과 개인 식별정보 삭제, 게시글·댓글 유지, 작성자를 ‘탈퇴한 회원’/‘Former Member’로 표시하는 것입니다. 화면의 공통 작성자 표시 함수는 이 표식을 양 언어로 처리합니다. 표식 지원만으로 기존 데이터가 익명화되는 것은 아닙니다.

## 현재 삭제를 막는 관계

로컬 SQL 초안 기준입니다. 실제 운영 DB 메타데이터 확인이 우선입니다.

| 테이블 | Auth 사용자 참조 | 처리 검토 |
| --- | --- | --- |
| member_profiles, member_languages | 프로필/Auth 연계, 기존 cascade | 프로필·언어 삭제, 다른 보관 사본 조사 |
| board_aliases | user_id PK, Auth FK | 별명과 사용자 연결 제거; 공개 닉네임 재사용 정책 결정 |
| board_posts, board_comments | author_id NOT NULL FK | 글/댓글은 유지, 작성자 FK nullable 전환 또는 비식별 구조 재설계 |
| board_reports | reporter_id NOT NULL FK | 신고 증빙·원문·상세의 식별정보와 보유 근거/기간 검토 |
| board_moderation_logs | actor_id NOT NULL FK | 운영 조치 감사 목적과 보유기간, 탈퇴 운영자의 표시 검토 |
| board_view_days | user_id 복합 PK/FK | 조회 중복 방지 식별정보 삭제/집계 처리 결정 |
| member_policy_acceptances (이번 초안) | user_id FK, 자동 cascade 없음 | 동의 증빙의 보유 근거/기간 결정 후 파기; 무기한 잔존 허용 아님 |
| 기타 행사·신청·파일·메시지·관리자 테이블 | 실제 스키마 전수 확인 필요 | 다른 팀 데이터의 관계·보관 정책 합의 |

`board_posts_protect`/`board_comments_protect` 트리거는 author_id/author_name 변경을 막습니다. 단순 UPDATE 또는 Auth 사용자 DELETE를 배포하면 실패하거나 부적절한 연쇄 삭제를 유발할 수 있습니다. 트리거를 전역 비활성화하는 방식은 사용하지 않습니다. `ON DELETE CASCADE`를 게시글에 추가하지 않습니다.

## 후속 구현 순서

1. 최근 재인증된 본인 요청을 서버에서 확인하고 요청 상태를 기록합니다. 공식 요청 창구 및 보유 정책은 먼저 승인해야 합니다. 입력한 user_id를 권한 근거로 사용하지 않습니다.
2. 실제 모든 FK, 트리거, RLS, 스토리지, 로그와 백업의 식별정보를 조사합니다. 계정에 대한 중복 탈퇴·글쓰기 경합을 직렬화하고 새 작업을 차단하는 상태 설계가 필요합니다.
3. 글·댓글의 author_id 연결을 제거할 수 있도록 검토된 스키마를 만듭니다. 작성자 표시에는 식별 가능한 기존 닉네임을 남기지 않고 표준 탈퇴 표식을 저장합니다. 일반 작성/수정 RPC에서는 이 변경을 계속 금지합니다. 원본 UUID나 닉네임을 공개 응답에 남기지 않습니다.
4. 별명·프로필·언어·조회일 식별정보를 제거합니다. 신고 원문·상세 및 글/댓글 본문 속 전화번호·이메일 등은 별도의 개인정보 요청 처리 기준으로 검토합니다. 작성자 이름만 바꾸어 본문까지 비식별화되었다고 주장하지 않습니다.
5. 보관 근거가 확정된 증빙만 제한 권한으로 정해진 기간 보관하고 나머지는 삭제합니다. 관련 테이블별 결정을 내리기 전에는 자동 처리를 공개하지 않습니다. 보관을 이유로 인증 계정이나 모든 증빙을 무조건 유지하지 않습니다.
6. 서비스 역할이 필요한 Auth Admin 삭제는 서버 전용으로 분리합니다. DB 트랜잭션과 외부 Auth 삭제는 하나의 원자적 트랜잭션이라고 보장할 수 없으므로 재시도 가능한 상태·부분 실패·세션 폐기·작업 복구를 설계합니다. 성공 확인 전 완료 메시지를 내보내지 않습니다.
7. 본인/타인/관리자 권한, 중복 요청, 마지막 글쓰기 경합, 각 FK, 부분 실패/재시도, public RPC의 식별정보 노출, 통계 유지 및 백업 파기 기한을 격리 환경에서 검증합니다.

실제 운영 기록은 이번 작업에서 수정·삭제하지 않았습니다. 이 문서는 실행 SQL이 아니며, 탈퇴 자동화를 활성화하는 승인 문서도 아닙니다.
