# A조 문자 발송 준비 — 가상 데이터

실제 발송 기능이 아니다. 운영 DB·PR28 납부 기능·문자 업체·발송 API·발송 이력 저장은 연결하지 않는다. 실제 발송 버튼은 항상 disabled이며 요청 핸들러가 없다. 화면 입력은 새로고침 시 초기화되며 템플릿 영구 저장은 범위 밖이다.

PR28 최신 문자 연동 문서(origin/codex/event-payment-refund 557b7fe)를 읽고 정책을 옮겼다. PR28 DB 적용·main 병합·운영 배포 보류는 유지한다.

선정: 같은 이벤트 + accepted + unpaid + 유료 양수 정수 금액 + 유효 전화번호 형식 + requested/approved/processed 환불 없음. paidAmount는 미납 판단 근거가 아니며 unpaid인데 금액 기록이 있는 모순은 제외하고 확인하도록 한다. unknown/확인대기/paid/refunded는 입금 요청 제외. 거절 환불만 있는 경우에는 다른 조건 충족 시 허용. 복합 키 eventId/source/id를 사용하고 번호 정규화 후 1명만 선택 가능하게 한다. 전체 선택은 화면 검색과 무관한 해당 이벤트의 조건 충족 전체임을 표시한다.

실제 연결 시 서버에서 전체 페이지 대상 조회, 환불 조회 페이지 처리, 선택 키 재검증, 발송 직전 최신 상태·금액·환불 재조회, 안내 건별 영구 중복 방지·성공/실패·재발송 기록, 업체 인증/발신번호/요금 기준을 구현해야 한다. 지금의 가상 배열 번호 중복 검사는 실제 발송 중복 방지 완료를 뜻하지 않는다. UTF-8 크기는 참고이며 SMS/LMS·과금 판정에 사용하지 않는다.

1. 문제사항: 납부 상태가 다른 신청자에게 동일한 입금 요청을 보내거나 제외 이유를 알기 어려움.
2. 개선 경험: 이벤트별 대상 판정·제외 사유·선택·이름/행사/금액 변수 치환·개인별 미리보기 구현.
3. 진행 과정: PR28 계약 확인 → 순수 정책 함수와 가상 데이터 → 관리자 UI → 자동 테스트/빌드 → 배포 후 가상 화면 검증.
4. 측정: 가상 단위 테스트6개로 상태·환불·키 격리·중복·30명 배열·변수 검증. 실제 성능/발송/도달/시간 절감 미측정. 실행 결과와 화면 검증은 최종 기록 참조.
5. 어려움과 해결: 납부 기능이 운영 미적용이므로 필드를 읽는 어댑터 대신 가상 데이터 모듈을 분리했다. 연락처 정규화와 복합 신청자 키로 중복/잘못된 환불 제외를 방지했다.
6. AI 활용: 합의된 납부 상태 의미를 검증 가능한 선정 규칙과 제외 사유로 구체화했다.
7. 포트폴리오: 납부 상태와 환불 조건을 반영한 문자 대상 선정·개인화 미리보기를 가상 데이터로 구현하고 실제 발송과 분리해 검증했습니다.
8. 자소서: 입금 안내의 오발송 가능성을 줄이기 위해 대상 기준을 정리하고 제외 사유를 화면에 표시했습니다. 운영 미적용 기능을 가상 데이터로 분리하고 중복·환불·변수 조건을 검토했습니다.

## 등록 이벤트 연결 (후속 작업)
문자 화면의 기본 목록은 관리자 권한으로 recruitment_events에서 실제 등록 이벤트를 조회합니다. 100개 단위로 끝까지 조회하며, 실패·빈 목록을 구분합니다. 선택하면 이벤트 제목·한국 시간 일정·장소·기존 참가비 안내 문구와 이벤트 정보/신청자 관리 링크를 표시합니다. 금액을 안내 문구에서 추정하거나 별도 저장하지 않습니다.
가상 대상 선정은 접힌 별도 연습 영역으로 유지합니다. 실제 이벤트와 가상 신청자는 연결하지 않습니다. 실제 신청자 문자 대상·납부액·환불 조회와 실제 발송은 미연결이며 PR28 보류를 유지합니다. 새 이벤트는 페이지 새로고침 후 반영됩니다.

## 메시징 화면·자동 문구 템플릿
이벤트 대상/번호 직접 입력 작성 방식을 제공하고 왼쪽 수신 대상, 오른쪽 템플릿·편집·미리보기로 구성합니다. 기본 문구 7종: 입금, 환불 요청 접수, 합격, 불합격, 이벤트, 참여 리마인드, 대기 안내. 버튼 클릭은 기존 편집 내용을 기본 문구로 교체하며 자동 전송·자동 수신자 선정·상태 변경을 실행하지 않습니다.
실제 이벤트의 제목·한국 시간 일정·장소·참가비 안내 문구를 변수에 반영합니다. 이름은 미리보기용 예시이며 실제 신청자를 자동 연결하지 않습니다. 미입력/알 수 없는 변수는 원문을 보존하고 안내합니다. 문의처·납부 기한은 임시 문구 작성용이며 DB에 저장하지 않습니다. 실제 금액을 문구에서 추정하지 않습니다.
직접 입력 번호는 줄바꿈/쉼표/세미콜론 구분 후 기존 정규화 함수로 형식 유효·중복·오류 개수를 표시하며 영구 저장하지 않습니다. 문자 발송·자동화·발송 로그·설정은 미구현으로 표시합니다. 실제 업체의 SMS/LMS·요금 기준을 가정하지 않습니다. PR28 보류 유지.
검증: 기존 정책 6개 + 문구 4개 = 자동 테스트 10개 통과. 신규 테스트는 7종 치환, 미입력·미지원 변수, 이벤트 전환, 환불 접수 표현을 검증합니다. 브라우저 확인 결과는 별도 최종 기록에 남깁니다.


## 실제 신청자 선택 연결
가상 연습 영역을 제거하고 관리자 인증을 재확인하는 조회 액션으로 실제 신청자 선택을 연결했습니다. 선택 이벤트 ID로 조회 범위를 제한하고 25명씩 페이지를 표시합니다. 이름·연락처 검색과 신청 상태 필터를 지원하며, 출처와 신청자 ID로 선택을 구분합니다. 이벤트 전환·검색·상태 변경 시 선택을 해제하고 페이지 이동 시 유지합니다. 전화번호가 아닌 연락처와 형식 오류 번호는 선택할 수 없습니다. 선택 인원과 중복 제거한 번호 수를 구분하며 첫 선택자의 이름으로 미리 봅니다.

납부·환불 조건에 따른 자동 대상 선정, 실제 발송, 개인정보 저장은 구현하지 않았습니다. PR #28 보류 유지. 관련 기존 자동 테스트 10개 및 lint·타입 검사를 수행했으며 운영 브라우저에서 실제 목록·선택·페이지 동작은 배포 후 별도 확인해야 합니다.

## 실제 연결 확장
2026-10-18 실제 문자 연결은 `docs/messaging-integration.md`를 참조한다. 기존 가상 데이터 도구는 그대로이며 실제 발송은 별도의 서버 권한 검사·DB 대기열·최종 확인을 거친다. SQL 적용 및 본인 도달 테스트 전에는 실제 발송/자동 알림이 꺼져 있다.
