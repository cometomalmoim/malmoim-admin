# 신청자 처리와 메시징 역할 분리

- 신청자 목록: 현재 페이지 체크 → 공통 작성창, 상태 변경 → 관련 문구 자동 선택, 최근 문자 이력.
- 연속 처리: 저장 안내의 ‘모아두고 계속 처리’를 선택하면 이후 입금/환불 상태 변경을 안내 대기열에 모음. 이벤트·안내 종류별 준비, 동일 신청자는 최신 종류로 대체, 최대 50명. 초과 대상은 일반 팝업으로 표시. 메모리 전용이며 브라우저 새로고침 시 초기화. 모으기는 자동 발송이 아니며 발송 후 운영진이 대상을 비움.
- 메시징: 문자 보내기 / 발송 기록 / 템플릿 관리. 연결 설정은 템플릿 관리 아래 접음. 작성 상태는 탭 전환 시 유지. 비용 검토 중에는 탭 전환 잠금.
- 공통 작성창: 빠른 문구 버튼, 기존 저장 문구 우선, 직접 수정, 개인 이력 펼치기, 최종 수신자/비용 확인. 저장 템플릿이 없는 기본 문구는 비용 조회 시 신규 템플릿으로 저장한다는 기존 안내 유지.
- 전체 이력: 현재 조회 페이지 최대 30건을 이벤트·템플릿 버전·언어별로 묶음. 한 발송 작업 전체를 집계하는 캠페인 테이블이 없으므로 작업 전체 건수로 표현하지 않음.
- 실패 재선택: 최신 failed 작업에서 신청자·이벤트를 다시 조회. 결과 불명·대기 건은 제외. 공통 작성창에서 새로 검토하며 자동 재시도/실제 발송 없음.
- 실제 환불 완료 DB가 연결되지 않았으므로 환불 안내 전용 작성창의 발송 제한 유지. 운영 상태만으로 완료 문자를 보내지 않음.

검증: 단위/액션 회귀 테스트 20개, 수정 파일 ESLint·타입·diff 검사. DB 스키마 변경 없음. 실제 SMS 발송 없음.
