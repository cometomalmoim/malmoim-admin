# 전자서명 3단계 — 브라우저 테스트

현재 `feat/events-yewon`에서만 작업한다. 사용자가 고정 브랜치 예외를 명시했고, 브랜치 전환·병합·커밋·push·PR은 하지 않았다.
DB·Supabase Storage·운영 서버·문자 서비스에 연결하지 않는다. 다른 조원 기능과 수료증·공통 관리자 메뉴·라우터·SQL·환경변수·`supabase/.temp/`은 변경하지 않았다.

## 사용 방법

프로젝트 루트에서 `npm run dev -- --webpack --hostname 127.0.0.1 --port 3187`을 실행하고
`http://127.0.0.1:3187/preview/pdf-fields`에 접속한다. 이전 단계와 같은 개발 전용 경로다.
로그인·Supabase 설정이 필요하지 않으며 기존 proxy의 인증 경로 밖에 있다.

1. PDF 선택. 모든 페이지 미리보기, 페이지 전환·확대·축소는 그대로 제공한다.
2. 새 필드 종류에서 서명(Signature)·이름(Name)·날짜(Date)를 선택해 그리거나 기본 필드를 추가한다.
3. 필드는 드래그 이동, 오른쪽 아래 크기 조절, 숫자 입력, 삭제·종류 변경이 가능하다.
4. 첨부된 활동 동의서와 정확히 같은 SHA-256의 PDF에는 ‘활동 동의서 기본 배치 적용’이 표시된다.
   원본 파일은 저장소/public/서버에 복사하지 않는다. 이름·서명·날짜 빈칸을 직접 수정할 수도 있다.
5. 세 종류가 각각 한 개 이상 있으면 ‘참가자 서명 화면 열기’를 선택한다.
6. 원문을 확인하고 네 항목에 각각 응답한다. 촬영·홍보는 동의/미동의 중 별도로 선택하며 초기값은 없다.
   미동의도 진행할 수 있다. 나머지 세 항목은 각각 확인해야 한다.
7. 고정된 가상 이름 ‘테스트 참가자’를 확인하고 테스트용 선/모양을 작성한다. 실제 이름·서명은 입력하지 않는다.
8. 서명 지우기·재작성 후 최종 확인한다. 한국 날짜, 동의 응답, 이름과 모든 서명 위치를 확인한다.
9. 최종 확인 체크 후 ‘확인 후 테스트 PDF 생성’. 완성 PDF 전체 페이지 미리보기와 즉시 다운로드를 제공한다.
10. 응답·서명 수정 시 생성 결과를 버리고 다시 확인·생성한다. 관리자 편집으로 복귀하면 참가자 테스트 상태는 사라진다.

PDF와 필드, 필기 좌표, 응답, 완료 시각, 생성 결과는 브라우저 메모리에만 둔다.
다운로드는 사용자 선택에 따라 로컬 파일을 저장하며 localStorage/DB/Storage 영구 저장은 없다.
출력용 Blob URL과 생성 PDF.js 문서는 컴포넌트 해제·수정 시 해제한다.

## PDF 출력과 독립 동의

원본 PDF의 디자인·문구·페이지·CropBox·회전을 유지하고 관리자 필드 위치에만 이름·서명·날짜를 덧그린다.
서명은 한 번 입력한 같은 벡터 경로를 모든 서명 필드에 적용하며, 회전된 페이지에서도 표시 방향을 맞춘다.
원본 좌표·회전·UserUnit을 최종 생성 시 다시 검증한다. 원본 바이트는 수정하지 않는다.

첨부 원문 1번은 촬영에 동의한다는 문구이므로, 서명 하나만으로 미동의 응답을 표현할 수 없다.
원문을 지우거나 바꾸는 대신 마지막에 **테스트 응답 확인 페이지**를 추가한다.
여기에 네 개의 개별 응답(촬영 미동의 포함), 가상 이름/ID, 날짜·시각, 문서 버전, 원본 해시를 기록한다.
서명 자체를 촬영 동의로 해석하지 않도록 UI와 추가 페이지에 명시한다.

완료 날짜는 최종 확인 단계의 브라우저 시각에서 Asia/Seoul 기준으로 계산해 스냅샷으로 고정한다.
기기 시계는 조작할 수 있으며 서버 시각·신원 인증·신뢰 타임스탬프를 대체하지 않는다.
원문 환불 문구는 제공받은 문서 내용 그대로이며 운영 정책이나 법률 적합성을 새로 확정한 것은 아니다.

- 전체 코드 테스트 122개 통과. 이번 단계 추가 테스트는 7개이며 기존 2단계 테스트 8개도 통과.
- 미응답 촬영 항목·누락된 개별 확인·빈 서명/점 하나·비정상 좌표·필드 누락 차단.
- 촬영 미동의 상태의 정상 진행, 최종 확인 스냅샷 변경 격리, 한국 날짜 경계 검사.
- 네 방향 회전·CropBox·UserUnit·원본 불변성·동일 서명 경로 반복·한글 이름/날짜 생성 검사.
- 다른 문서 해시·변조된 페이지 좌표/날짜·가상 참가자가 아닌 값의 PDF 생성 거부.
- TypeScript 통과. `eslint src tests next.config.ts eslint.config.mjs`: 오류 0개, 기존 suggestions 액션 경고 2개 유지.
- 환경변수 없는 `work/pdf-fields-check` 사본의 Webpack 프로덕션 빌드 통과.
- 앱 브라우저에서 실제 첨부 PDF 선택, 기본 배치, 참가자 화면, 촬영 미동의, 개별 확인, 빈 서명 차단,
  마우스 필기, 지우기·재작성, 최종 확인 전 생성 차단, PDF 생성과 실제 다운로드를 확인했다.
- 다운로드 결과를 pypdf로 다시 열어 2페이지·테스트 이름/날짜·촬영 미동의 기록을 확인했다.
- 별도 가상 결과는 같은 서명 두 곳 적용을 포함해 Poppler로 두 페이지를 렌더링하여 시각 확인했다.
- 실제 휴대폰 터치/Safari, 390px 실측은 미검증이다. Pointer Events와 반응형 CSS로 구현했지만 실기기 검증을 대체하지 않는다.
- DB 테스트·SQL·문자 발송·운영 접근은 수행하지 않았다.

## 미구현·후속 검증

참가자 본인 인증, 개인별 링크, 실제 신청자 이름 연결, 서버 완료 시각, 문서/동의 버전 영구 관리,
감사 이력·해시 보관, DB/Storage, 문자, 운영 권한·다운로드 보관 정책, 인증서 기반 디지털 서명은 미구현이다.
임의의 다른 PDF에서 기존 디지털 서명의 효력을 유지하는 기능도 제공하지 않는다.
현재 네 항목은 말모임 활동 동의서 테스트에 고정되어 있으며 일반 문서별 동의 문구 편집은 별도 단계다.
서명 획수/좌표 수와 원본 파일 제한은 있지만 복잡한 PDF의 메인 스레드 파싱·출력 용량을 완전히 격리하지는 못한다.
