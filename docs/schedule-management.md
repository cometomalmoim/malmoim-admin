# 스케줄 관리

## 적용

기존 SQL 001~017 적용 상태를 확인하고 `supabase/018_schedule_management.sql` 전체를 Supabase SQL Editor에서 한 번 실행한다. 실패 시 전체 트랜잭션이 롤백된다. 운영 DB 자동 적용 도구는 포함하지 않는다.

시간 입력은 018 적용 후 `supabase/019_schedule_times.sql` 전체를 한 번 실행해 활성화한다. 이 SQL은 nullable `start_time`/`end_time` 컬럼과 저장·연동 함수를 갱신한다. 기존 날짜 전용 일정은 유지하며, 019 미적용 상태에서 시간 저장을 요청하면 적용 안내를 표시해 입력 시간이 조용히 누락되지 않도록 한다.

이 마이그레이션은 일정/태그/운영진 표시 이름과 관리자 전용 RPC를 만들고 기존 이벤트의 행사·모집 기간을 일정으로 반영한다. 이벤트 공개, 신청 접수 활성화 상태는 변경하지 않는다. 일정 변경은 Supabase Realtime private broadcast를 사용하므로 `realtime.send`, `realtime.messages`, `realtime.topic()`이 제공되는 Supabase 환경이 필요하다. 임의의 Postgres에서 적용할 때에는 해당 기능을 별도로 제공해야 한다.

운영진 표시 이름은 기존/신규 관리자 모두 `운영진 UUID앞8자리`로 초기화한다. DB 운영자가 `admin_profiles.display_name`에 실제 이름을 등록할 수 있다. 앱 사용자의 이름 수정 권한은 본인에게만 주어진다. 관리자 등록 권한은 기존대로 DB 운영자에게만 있다.

적용 후 관리자 두 계정으로 `/admin/schedule`을 열어 일정 등록, 태그 변경의 다른 화면 반영, 권한 제거 후 접근 거부를 확인한다. 운영 DB 적용과 실제 두 브라우저 Realtime 검증은 로컬 SQL 테스트와 별도로 필요하다.

## 동작

- 일정 종료일은 포함한다. 시작일과 종료일이 같으면 당일 일정이다.
- 시작 시간과 끝나는 시간은 각각 선택 입력이며 한국시간의 시·분(00:00~23:59)으로 저장한다. 둘 다 비우면 날짜 전용, 한쪽만 입력해도 저장 가능하다. 같은 날짜에서 두 시간을 입력한 경우 종료 시간이 시작보다 이르면 거부한다. 날짜가 다르면 야간 일정도 허용한다. 시간 필드를 명시적으로 비우면 기존 시간을 제거하며, 이전 클라이언트가 키를 생략한 경우 DB가 기존 시간을 보존한다.
- 행사/모집 시각은 한국시간으로 변환하며 종료 시각 직전 날짜까지 표시한다. 10/19 00:00 종료는 10/18까지이다.
- 이벤트 연동 시간은 원본 이벤트에서만 수정한다. 자정 종료는 기존 포함일 규칙에 맞춰 전날 23:59로 표시하며, 목록의 시간은 분 단위로 표시한다.
- 태그는 필수, 담당자는 미지정 또는 운영진 한 명이다. 이름/색상은 태그에서 매번 조회해 과거 일정에도 반영한다.
- 주 경계를 넘는 기간 바는 이어짐 화살표를 표시한다. 3행을 넘는 일정은 날짜별 `+N개`를 누르면 우측 패널에서 전체를 확인한다.
- 최초 진입 시 상세 패널을 숨기되 우측 열은 빈 공간으로 유지한다. 패널 열기/닫기에 따라 캘린더·하단 카드의 폭은 바뀌지 않는다. 날짜 클릭은 날짜만 선택하고, 일정 클릭·`+ 일정 등록`·`+N개` 클릭 시 상세 패널을 연다. `✕ 닫기`로 패널을 닫으면 등록 버튼으로 포커스를 돌려준다. 삭제·숨김 후에도 패널을 닫는다. 태그 관리는 별도 모달을 유지한다.
- 전체 영역은 최대 1120px이며, 캘린더와 아래 D-Day 카드는 같은 그리드 열을 사용해 항상 폭이 일치한다. 740px 이하에서는 패널을 메인 열 아래로 배치하고 열릴 때 해당 패널로 스크롤한다. 패널 외곽은 라운드 카드가 감싸고 내부 영역만 스크롤한다.
- D-Day 카드는 조회 중인 월과 관계없이 모든 숨기지 않은 일정을 대상으로 한다. 시작일까지 한국시간 날짜 차이를 계산해 임박순으로 정렬하고, 오늘 시작·진행 중인 일정은 `D-Day`로 표시한다. 이미 시작한 기간 일정에는 `진행 중`도 표시한다. 종료일이 오늘인 일정은 아직 마감되지 않은 것으로 취급한다.
- 다가오는 일정과 마감 일정은 독립된 흰색 카드이며 각각 임박한 5개·최근 마감된 5개만 표시한다. 뱃지 | 제목 | 태그 | 날짜/기간 | 상태를 한 줄로 표시하고 좁은 화면에서는 말줄임한다. 항목을 클릭하면 전체 정보를 상세 패널에서 확인한다.
- 마감 일정 전체보기 모달에서는 제목·태그·비고 검색과 종료일 기준 최근 1개월/3개월/올해/전체 필터를 함께 사용한다. 최근 개월 수는 달력 기준으로 계산하며 월말은 해당 달의 마지막 날짜로 보정한다. 검색 결과는 최근 종료일 순으로 20개씩 확장한다. 모달 항목 선택 시 모달을 닫고 해당 월의 상세 패널을 연다. 자정을 지난 화면도 1분 간격·창 포커스 시 오늘 날짜를 갱신한다.
- 다가오는 일정 전체보기 모달도 임박순 전체 목록과 별도의 검색창을 제공한다. 두 전체보기 모달은 캘린더의 통합 검색과 독립적으로 전체 일정을 조회한다.
- 캘린더 우측 상단 통합 검색은 제목·태그·비고를 즉시 검색하고 전체/다가오는/마감 범위를 선택한다. 현재 월과 무관한 검색 결과를 캘린더 위에 표시하고 캘린더 칩·하단 두 목록에도 함께 적용한다. 검색 초기화로 전체 표시를 복원한다. 행은 공통 그리드 열을 사용해 긴 제목·태그·기간에도 동일한 열 정렬을 유지하며 말줄임과 툴팁, 상세 패널로 전체 정보를 확인한다.
- 사용 중 태그 삭제는 대체 태그로 모든 일정(숨긴 일정 포함)을 옮긴다. 기본 태그 삭제는 일반 커스텀 태그를 대체 태그로 선택해야 한다. 기본 역할도 이전하므로 이후 자동 일정에 계속 사용할 수 있다.
- 행사와 모집 기간은 각각 1개씩 동기화한다. 날짜 없는 기간과 테스트 이벤트는 표시하지 않는다. 모집 기간 제거 시 대응 일정을 제거한다.
- 자동 일정의 제목과 기간은 원본 이벤트 화면에서 수정한다. 캘린더에서는 태그/담당자/비고를 관리한다. 원본 변경은 이 값들과 숨김 상태를 유지한다.
- 수동 일정은 삭제하고, 자동 일정은 원본을 유지한 채 숨긴다. 숨김 복구 UI는 제공하지 않는다. 운영자는 필요 시 DB에서 `hidden_at=null`로 복구할 수 있다.
- 이벤트를 실제 삭제하면 연동 일정도 삭제된다. 기존 이벤트 삭제 제한은 유지된다.
- 저장 버전이 다르면 수정/삭제를 거절한다. 모달을 닫고 최신 일정을 다시 열어 재시도한다.

## 권한과 실시간

일정/태그의 직접 쓰기 권한은 주지 않는다. 각 RPC는 관리자 여부를 다시 확인하고 출처·작성자·수정 버전을 보호한다. 자동 연동 트리거는 이벤트 쓰기와 같은 트랜잭션에서 수행된다.

Realtime 메시지는 데이터 없이 갱신 신호만 전송한다. 관리자만 private 채널을 구독할 수 있고, 실제 데이터는 매번 권한을 확인하는 Server Action으로 조회한다. 서버의 HTTP-only 로그인 쿠키는 유지한다. 검증된 관리자의 단기 access JWT만 메모리에 전달해 Realtime 인증에 사용하고 브라우저 스토리지에 저장하지 않는다. 4분마다 갱신하고 화면 종료 시 구독을 해제한다. 창 포커스 시에도 재조회한다.

## 검증

```powershell
node --experimental-strip-types --test tests/schedules.test.mjs
node --experimental-strip-types --test tests/schedule-agenda.test.mjs
npm install --prefix work/sql --no-save @electric-sql/pglite
node tests/schedules-db.mjs
npm run lint
npm run build
```

DB 테스트는 서비스 DB/키를 사용하지 않는 임시 PGlite다. 실제 이벤트 테이블 마이그레이션을 사용해 RLS, RPC 보호, 충돌, 태그 교체, 동기화 및 자정 경계를 검증한다. Realtime 함수는 stub으로 실행하므로 실제 네트워크 전달은 검증하지 않는다. `work/`는 Git에서 제외되어 앱 의존성에 포함되지 않는다.

개발 모드의 `/preview/admin/schedule`에서 가상 일정/태그로 화면을 확인할 수 있다. 미리보기는 저장하지 않으며 운영 환경에서는 404다.
